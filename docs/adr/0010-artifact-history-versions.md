# 0010 · 产物历史版本：每次改写之前先存一版

> 与 [ADR 0009](./0009-trace-artifacts-stay-out-of-outputs.md) 配套：0009 定"留痕不进产物列表"，
> 本票定"历史版本怎么产生、放哪、叫什么"。判据同出一处（`pure/buckets.ts`）。

## 背景

配置表是**二进制、就地改** —— 改了旧版就真没了，而且不像文档那样能看 diff。
文档类产物（成稿 / 定稿 / 宣讲 HTML）虽然文件名里带日期（`_20261009.md` / `_20261010_定稿.md`），
但那只是"这一版是哪天写的"：**同一份文档被改写多次时，同样没有旧版可退**
（联盟讨伐的定稿在 10-10 → 10-12 之间被改过六轮，旧样子只散落在审查报告的叙述里）。

工具链里原本只有一个**一次性**副本：写入引擎的 `<表名>.backup.<时间戳>.xlsx` ——
它是为"验收对比 + 失败回滚"生的，验收一过就没用了（`策划配置\` 里现在一个 backup 都不剩）。

**用户口径（2026-10-12）**：**每次产物的修改都留下历史版本**，按 `<日期>_<序号>` 区分，
例如 `A079-联盟讨伐_20261012_1.xlsx`；放在 `gdd\` 目录下。

## 决定

1. **命名**：`<当前版文件名>_<YYYYMMDD>_<序号>.<ext>`，序号 = 该产物**当天的第几份**（扫目录算）。
   后缀加在"去**最后一段**扩展名"之后（`x.content.json` → `x.content_20261012_1.json`）。
   ★ **当前版的名字不带日期**（2026-10-12 用户口径修正，两位用户的追问把它逼出来的）：
   定稿就叫 `<主题>_定稿.md`、成稿就叫 `<主题>.md` —— 日期**只出现在版本后缀里**。
   否则版本名会出现**两个日期**（`联盟讨伐_20261010_定稿_20261012_1.md`：一个是产物身份、一个是存版时间），
   看着像重复；而这四类产物**本来就只有一份**，一个日期足够。
   ★ **范围只有四类**：成稿 / 定稿 / 宣讲稿 / 配置表 —— `analysis\` 的分析产物、界面图、审查报告**不要求**存版。
2. **时机**：**改写之前**存；存的是**被替换掉的那一版**（于是随时能退回上一版）。
   首次创建不算修改、不存；**不追溯**（老版本不回填）。
3. **落点**：**产物所在的那个桶，平铺**（`gdd\` 的产物版本就在 `gdd\`）。
   **`config_root` 里的既有表例外** —— 版本进**该功能的 `gdd\`**：配置目录是程序运行时读的，
   多出来的工作簿会进导出 / INDEX / 引用扫描的视野。
4. **工具**：[`history_snapshot.py`](../skills/sr-askme/tools/history_snapshot.py)
   （`--dry-run` / `--dir` / `--selftest`）—— 读目录实况算序号，**人和 agent 用同一条命令**。
5. **谁触发**：
   - **改表**（`/sr-config`）→ **写入引擎自动留**：**验收通过之后**从**备份**派生一份，落
     `plan.json` 的 `history_dir`。写入没成（已回滚）**不会白留一版**；留版本失败**不阻塞**写入，但如实报出来。
   - **改文档 / HTML / 图片** → **本会话的 agent 动笔之前跑一次命令**
     （各 skill 的「产出规范」节挂了指针，与 `decision-recording.md` 同一处）。

   ★ **规矩靠三道落地，缺一道就会漏**（用户 2026-10-12 追问"只有 sr-askme 是否足够"）：
   | 道 | 管什么 | 本票 |
   |---|---|---|
   | ① **persona**（策划模式，每轮在上下文） | **跨 skill 的兜底** —— 与当前跑哪个 skill 无关 | `cordis.patch.yml` 新增「产物历史版本契约」 |
   | ② **各 skill 挂指针** | agent 在该 skill 工作时看得到 | 10 处（8 个 sr-* 的「产出规范」节 + sr-config + 配套 `skill-hero-config`） |
   | ③ **单一权威文件** | 细节只写一处，改的时候不用改两遍 | `sr-askme/references/version-history.md`（skill 与 persona 都只给指针，**不复述规则**） |

   这是本仓库既有结论的复用：`cordis.patch.yml` 里「决策记录契约」那段注释写的就是
   "persona 是**兜底机制**：每轮都在上下文里，与走哪个 skill 无关"。
6. **面板口径**：历史版本是**过程留痕** —— 不列条目、只在页签底部报数（接 ADR 0009）。
   判据 `historyVersionOf`（`pure/buckets.ts`）：**去掉全部扩展名后**，名字尾部是 `_<8 位日期>_<数字>`。
   ★ 它**必须最先判**：`联盟讨伐_20261010_定稿_20261012_1.md` 已经**不再匹配** `_定稿.md` ——
   不先拦就会被算成一份**成稿**；`A079-联盟讨伐_20261012_1.xlsx` 会被算成**另一张配置表**。
7. **扫描排除**：`sr-config` 的配置目录扫描**多排除一类**（名字尾部是 `_<8 位日期>_<序号>`），
   与第 3 条"版本不落配置目录"构成**双保险**。
8. **与「换版」分清**：`sr-gdd-fix` 原来那句"用户要求留版本时，定稿另存为 `<主题>_<新日期>_定稿.md`"
   说的是**换版** —— 新文件 `active`、旧文件 `archived`，**改变"当前定稿是哪一份"**。
   两者目的不同，**措辞分开**："留版本"以后专指历史版本，"换版"专指换当前那一份。

## Considered Options

- **只给表做版本**（改动最小）—— 用户明确要"所有产物都留"；文档被改写同样没有旧版可退。
- **同目录开子文件夹（`gdd\历史\`）** —— 天然不参与扫描、目录更干净；用户口径是"直接放到 `gdd\` 目录下"。
- **维护一份版本索引文件**（记录每份产物的版本序列）—— 索引会与目录实况漂移，
  而序号完全能从目录实况算出来（**真相只有一个来源**）。
- **把 `.backup.` 改名当版本用** —— 它的落点是"目标表同目录"（既有表就在配置目录 ⇒ 进扫描视野），
  且只在写入前产生、验收失败还会被用来恢复；职责不同，不该合并。

## Consequences

- **代价**：功能目录会持续长大（一份定稿 52 KB、一张表 26 KB，改 10 次就是 10 份）。
  这是"能退回去"的价钱，用户明确要；真要清理就**按版本文件名成批删**。
- **代价**：多一条要遵守的纪律（改文档前跑一次命令）。靠"各 skill 挂指针 + 一条命令"降低漏的概率；
  **改表那条线已经自动化**，不靠人记。
- **好处**：任何产物都能退回上一版；"这张表 / 这稿当天被改了几次、每次改前长什么样"变成**可查的事实**。
- **连带修掉一处既有脆弱点**（实测撞上的）：`excel_com_edit.py` / `verify_table_edit.py` /
  `selftest_excel_com.py` 在**被管道采集**时按 GBK 输出 `✓` `⇒` 会抛 UnicodeEncodeError ——
  引擎崩在半路、**退出码变成 1**，看上去跟"验收失败"一模一样（自检有三格因此**时红时绿**）。
  三处统一为"**非 tty 就输出 UTF-8**"（终端仍走系统默认，两边都能读）。
- **回归钉子**：`pure-buckets`（判据正反例）· `pure-artifacts`（版本进留痕账）·
  `load-dashboard-counts`（版本**不许**进产物类）+ `history_snapshot.py --selftest`（12 例）
  + `selftest_excel_com.py`（8 例，且**要求在管道里跑也全绿**）。
