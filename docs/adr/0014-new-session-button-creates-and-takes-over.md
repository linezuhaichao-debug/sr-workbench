# 0014 · 详情页〔打开会话〕改成〔新建会话〕：会话由面板造，并接管控制

> ★ **同日后续（2026-10-13）：本 ADR 的第 3 条"建完就接管，指令以后发给它"被 [ADR 0015](./0015-one-session-per-dispatch.md) 改了** ——
> 四入口现在**每次派活都另起一条会话**（也走这里这条创建路），所以"接管"只剩"面板记得最近一条是哪条"的意思。
> 本 ADR 其余部分（按钮改名的理由、有降级就不切走、单航班锁用独立键、代价是面板不再有"跳到当前工作会话"的入口）继续有效。

> 触发：2026-10-13 用户指令 ——「策划工作台 功能内部面板的右上角「打开会话按钮」改成「新建会话」，
> 目的是**通过工作台创建会话**，这样会话会建在对应功能的工作区并给会话开策划模式，**会收到工作台的控制**」。

## 背景

那颗按钮的历史名字换过两次：〔打开工作会话〕→〔打开会话〕（2026-10-10 按"2 + 4 字、与卡片墙同一套"的
头部按钮口径改短）。但**动作一直只有一件**：`uiWorkspace.openSession(cachedSid)` ——
跳到**已经存在**的那条工作会话。于是有两个缺口：

1. **面板上没有"造一条会话"的入口。** `sessionId` 为空时那颗按钮**根本不渲染**
   （旧写法 `props.sessionId ? Btn(…) : null`），而"这个功能还没建工作会话"恰恰是最需要它的时刻。
   面板上唯一会建会话的地方是**第一次发头脑风暴指令**时的 `ensureWorkSession` —— 那是**被动**的：
   用户想先跟 agent 说两句（还不发那四条入口指令）时，没有办法。
2. **用户自己建的会话永远"不受面板控制"。** 工作会话被面板认领要同时满足三样：
   工作区 / cwd = 功能目录、预设 =「策划模式」、成为面板发指令的目标。用户在侧边栏手工建一条，
   三样一样都拿不到；而面板**绝不认领用户的对话**（`pure/sessionpick.ts` 的纪律：
   认领凭据只有"标题前缀"与"面板自己写的缓存"，用户故事 23）。⇒ 手工建的会话永远在面板之外。

## 决定

1. **那颗按钮改成〔新建会话〕，并且总是渲染**（不再依赖 `sessionId`）。它是**唯一**由面板发起的
   "造一条工作会话"入口。
2. **建的动作复用 `createSessionAt`**（与「新建功能」同一条路，一处不抄两份）：
   `workspace.create(功能根)` → `session.create({ workspaceId, agentPreset: "sr-workbench" })`
   → `session.rename("策划工作台·工作（<主题>）")` → 切完全权限 → 并入侧边栏 store。
   **期间不发任何指令**（面板不替用户说话 —— 那是"头脑风暴四入口"唯一那条出口的事）。
3. **建完就接管**：组合根里的映射（`WORK_SESSION`）与本地缓存（`localStorage['sr-wb.work.v1']`）
   都改指新的一条 ⇒ 头脑风暴四入口的指令以后发给**它**（这就是用户说的"会收到工作台的控制"）。
   **旧的那条不删、不归档、不改名**（面板只建不删），只是不再收指令；
   界面**如实说一句**（"原来那条没动、还在侧边栏，面板以后只往新的发指令"）——换指向是有后果的，不能默默发生。
4. **单航班锁用独立的键**（`new-work:`）：它与 `ensureWorkSession`（"没有才建"）是**两件事**，
   不能合并成同一次请求；连点两下的语义就是"建两条"（误点由按钮的置灰兜住）。
5. **建成功且没有任何降级**，才把用户切过去（`uiWorkspace.openSession`）；**有降级就留在面板**把话说清。
   理由不是美观：切走 = 面板**重挂载**，`notice` 是组件 state ⇒ 那句提示会随卸载一起消失，
   用户就永远看不到"预设没挂上 / 权限没切上 / 侧边栏没同步上"这类**有后果的降级**
   （`warn` 与 `note` 的分寸见 ADR 0013）。

## Considered Options

- **保留〔打开会话〕、另加一颗〔新建会话〕**：否 —— 用户口径是"**改**"，且头部那两位是一套
  （2 + 4 字、同一个 `HEAD_BTN_H` 等高、`alignSelf: "center"` 对齐），再加一颗就破了这套对称。
  **代价如实记**：面板上不再有"跳到当前工作会话"的入口 —— 回那条会话走侧边栏
  （它就挂在功能的专属工作区下面），面板侧只剩〔＋ 新建〕。
- **一颗按钮两种行为**（有会话就打开、没有就新建）：否 —— 点下去之前不知道会发生什么，
  〔打开工作会话〕这个旧名字正是这么来的。
- **建之前弹一次确认**（"已经有会话了，确定另起一条？"）：否 —— 新建会话**可逆且无破坏**
  （旧的不动，随时回侧边栏），确认框换不来等量的安全。判据与 ADR 0013 拒绝"清残留前先确认"是同一条：
  **动作可逆就不拦**。
- **复用 `ensureWorkSession` 那把锁**：否 —— 它语义是"没有才建"，会把用户这一下与并发的一次
  头脑风暴发送合并成同一次，于是"再点一次另起一条"变成了"回到旧的那条"。

## Consequences

- **"每个功能一条工作会话"改成"面板指向的那一条"**：同一个功能下**可以有多条**（用户每点一次就多一条）。
  认领不会因此认错 —— `pickWorkSession` 本来就是"缓存优先，其次标题取最近更新"
  （`CONTEXT.md` §工作会话、`src/pure/sessionpick.ts` 同步改了措辞）。
- 旧会话成为侧边栏里一条普通会话（标题仍可辨认），**不会被清理** ——
  残留清理只在"功能目录已经不在磁盘上"时动手（ADR 0013）。
- **判据**（这一轮新增/改动的用例）：
  · `test/create-flow.test.ts` 两条：建在功能根 + 策划模式 + 改名 + **成为四入口指令的目标**；
    再点一次 = 另起一条（旧的不删不动、面板改指新的）。
  · `test/panel-view-timing.test.ts` 两条（真 Panel 上点那颗按钮）：没有降级 ⇒ 建完**切过去**；
    `rename` 被拒 ⇒ **留在面板**报"改名失败"且不切走。
  · `test/seam.test.ts`：新名〔新建会话〕在、三个旧名（〔技能用法〕〔打开工作会话〕〔打开会话〕）
    都不许再当按钮文案；那颗按钮的文案是**条件式**（新建中… / 新建会话），判据改成取它前后各 300 字来钉几何。
  · `tools/render-smoke.mjs`：详情那一遍断言屏幕上真有〔新建会话〕（它现在**总是**渲染，这一遍就能盯住）。
- 未做（等真要时再立票）：
  · 面板不显示"当前指的是哪一条工作会话"（会话名只在侧边栏看得到；`sessionNote` 只说有没有）；
  · 面板仍不给"打开当前工作会话"的入口（侧边栏承担）；
  · 多条工作会话的**收拢**（比如把不再收指令的那些归档）—— 那是"面板只建不删"之外的动作，要先有用户口径。
