## 背景

2026-10-15 圣物系统的 UE 稿（Figma「SR-圣物系统」12 屏 + 逐屏标注）回写定稿后，
用户连续追出多处错漏，最终实际改动 **23 行 + 删 1 行**，另有后续多轮修正。
逐屏溯源后，把错漏归成四类与四个根因：

| 类型 | 实例 |
| --- | --- |
| 定稿写了图上没有 | 装配页候选列表、占用转移二次确认弹窗、星级进度文字、技能解锁条件文字 |
| 图上有定稿没写 | 卸下＝红圈禁止符；替换页 / 装配页按钮按状态切文案（装配 / 替换 / 前往获取） |
| 文案层口径乱 | 「技能效果（装配后生效）」多写了括号句、「可激活」文字缺失、图鉴标题缺失、装配成功 tips |
| 同屏多行为未写全 | UI-M12 被两处复用（抽卡首次获得 / 图鉴可激活点击）没写进触发条件 |

根因：

1. **增量改写留下旧口径** —— §5 重写过，但被删元素的连带项（§4 R2、§7 键）没同步；
2. **判"有没有"的粒度太粗** —— 只判图形，不判文字；用户三次追出的都是"图上只有图形、没有文字"；
3. **跨源误用** —— Figma 导出虽未含标注带，但 `界面说明.md` 里写着「圣物 n 星解锁」这类**对图形的文字诠释**，
   被当成了"画面上有这行字"；
4. **自造含混标签** —— 用一个「按新图待补」混装"设计遗漏"与"规则该废"，用户得逐条来纠。

## 决定

### 一、两源分工（判据，不产生任何记录工作）

| 证据源 | 只看它判什么 | 不得用它证明 |
| --- | --- | --- |
| **画面本体**（导出截图） | **画面上有没有**（某控件 / 某行字此刻出现与否） | 状态全集 |
| **标注带 / 界面说明** | **该有哪些状态、文案、交互**（全不全） | 画面上真的印了某行字 |

冲突时的裁决（写进 D21）：

| 画面本体 | 标注 / 说明 | 裁决 |
| --- | --- | --- |
| 有 | 无 | `待设计确认`（疑漏标） |
| 无 | 有 · **固定文案** | `保留·待补图`（真遗漏） |
| 无 | 有 · **状态变体** | 正常（图只是样本）→ 把状态全体写进 §5 / §7 的「触发」列 |
| 无 | 无 | `新增需求` |

### 二、三类分治（文案层）

- **固定文案**（页面 / 区标题这类不随状态变的）→ 图上**必须**能找到，找不到＝真遗漏；
- **状态变体文案**（同一位置多状态不同字）→ **不要求**图上出现，要求**状态枚举写全**（产出「状态 × 文案」矩阵）；
- **新增需求文案**（图外补充）→ 图上必然没有，标 `新增需求`，**不算遗漏**。

**硬规矩**：一屏只画一个状态 ⇒ **不得以"图上没有"删掉状态变体文案**。

### 三、三类标注（D22，替代任何自造的"待补 / 待确认"）

`保留·待补图`（补齐图单）· `待设计确认`（对设计的具体提问）· `已按新图删除`（连带处理 §7 键与 §4 规则）。

### 四、流程落点（元教训）

**判据修正与流程步骤落在「实际执行这次改动的 skill」上，不落在「形态基准的 owner」上。**
界面回写、定稿维护发生在 `sr-gdd-fix`，故对图流程进 fix 的第 4 步与第 5 步复核清单；
`sr-gdd-ai` 是首次整合 + 定稿门，**本次一处未动**。

### 五、不做素材台账（职责边界）

**不要求策划给设计素材做资产台账**（不算 sha256、不记 Figma node、不建导出记录）——
素材是别人给的输入。防"新旧素材混用"靠两条零成本约束：① 核对只认 `evidence\` 真源，`gdd\` 副本不参与判断；
② §5 图注指向真源。**"标注带在不在"是核对方法的前提（决定怎么核），不是登记项。**
