# 0009 · 过程留痕留在功能目录里，但不进「最终产物」列表

> ★ **2026-10-12 修正（重要）**：本 ADR 说的"留痕"**不含产物历史版本** —— 那是**产物本身的一代**，
> 用户明确要求"**我就是为了在最终产物里看历史版本才改这个的**"，它**归它当前版所在的那一类显示**
> （定稿的旧版进「定稿」，当前版第一、旧版按版本号倒序，标 `〔当前〕`/`〔历史版本〕`）。
> 见 [ADR 0010](./0010-artifact-history-versions.md) 与 `skills/sr-askme/references/version-history.md` §七。
> **本 ADR 只管过程留痕四类**：变更集 / 读回验收报告 / 审查报告 / 修订点清单 —— 它们**仍然不列条目、只报数**。

## 背景

v5 的「最终产物」按文件名把 `analysis\` + `gdd\` 的文件分成五类
（头脑风暴的产物 / 成稿 / 定稿 / 宣讲稿 / 配置表），认不出的进默认折叠的「其它」组，
纪律是"**一个文件都不许静默丢**"。

2026-10-12 用户连着问了三批文件"有存在的必要吗"：`联盟讨伐_20261010_审查.md`、
三份 `CS-*.yaml` 变更集、两份 `*_读回验收报告.md`。逐份查过之后结论都是**该留**：

- **审查报告**是 `sr-gdd-review` 的唯一产出、定稿门必经的输入 —— 门虽然过了，
  但"这稿被独立审查过、V1–V13 逐项结论是什么"只此一份；
- **变更集**是一次配置写入的账本（逐项 before/after + 审批 + 验收 + 未办项），
  **配置表本身不带历史** —— 尤其新建的表还没上线时，它是"这张表跟老版差在哪"的唯一答案；
- **读回验收报告**与变更集成对（一份管"改什么"、一份管"改成了没有"），
  而且记着真踩过的坑（openpyxl 往返写丢掉公式缓存值 → 改表一律走 Excel COM）。

但用户同时明确：**这些在策划工作台里不需要显示**。

## 决定

**留痕留在功能目录里（位置不变），但不进「最终产物」列表；面板只在页签底部报数。**

1. 判据新增一档：`traceArtifactOf`（`pure/buckets.ts`）认四类 ——
   变更集 `CS-<YYYYMMDD>-<NNN>.yaml` · 读回验收报告 `*_读回验收报告*.md` ·
   审查报告 `*_审查.md` · 修订点清单 `*_修订点.md`；它在 `outputGroupOf` 里**先于**其它判据拦下。
2. 「配置表」这一类从此**只装表本体**（`.xlsx` / `.xlsm` / `.csv`）。
3. `featureArtifacts` 返回一个**不进 `groups`** 的 `trace` 账（`count` / `summary` / `files` / `allPaths`）；
   **`total + trace.count` 必须等于两个桶里的全部文件** —— "不静默丢"这条纪律改由**报数**兜住。
4. 页签底部一行小字：「另有 N 份过程留痕（3 份变更集 · 2 份读回验收报告 · 1 份审查报告）不在上面列出 ——
   它们是过程档案、不是这个功能的产物；文件在 `gdd\` 里，要看就点上面的〔打开路径〕。」
   没有留痕时整行不出现（干净的功能看不到它）。
5. 卡片墙的 counts 同步带上 `trace`：**不展示**，但与详情页**同一份判据** —— 不许两个数
   （这条有专门的回归钉子）。

## Considered Options

- **继续按「配置表」一类列出来**（改动最小）—— 用户看到的就是这个形态，明确说不要：
  工作台要回答的是"这个功能产出了什么"，变更集与验收报告不是产物。
- **把它们移出功能目录**（挪进 `evidence\` 或 `.tmp\`）—— 会与 `sr-gdd-review` / `sr-config`
  写死的产出落点（`gdd\<主题>_<日期>_审查.md`、`gdd\CS-*.yaml`）打架，得连规范一起改；
  而且"审查报告与定稿同层"本身就是定稿门的设计（报告随定稿一并呈门）。
- **直接从面板消失、不报数** —— 破"一个文件都不许静默丢"的老纪律（本仓库为它写过回归钉子）。
- **塞进默认折叠的「其它」组** —— 用户口径是"不需要显示"，塞进折叠组仍然是显示。

## Consequences

- **代价**：面板上「最终产物（N）」这个数字会变小（联盟讨伐 13 → 7）——
  这是对的（那是**产物**的数），但记得住文件数的人会以为面板漏了 ⇒ 靠底部那行报数说清。
- **代价**：判据多了一档，"哪个文件算留痕"这条线要维护；正则只写在 `traceKindOf` 一处，界面不另判。
- **好处**：工作台回到"这个功能产出了什么"这一个问题；留痕一个不丢、可追溯（文件仍在 `gdd\`）。
- **连带修掉一处陈旧**：`client.js` 里硬编码的「其它（不属上面**四类**）」标签改成**取组自己的 `label`** ——
  「配置表」加进来之后它已经说错了一次（判据两份的老毛病：改了一处、另一处没跟上）。
- **回归钉子**：`pure-artifacts` / `pure-buckets` / `load-feature` / `load-dashboard-counts` 四支用例
  ＋ 渲染冒烟的真数据那遍（正面钉"报数那句话真出现"，反面钉"留痕不许作为条目出现"）。
