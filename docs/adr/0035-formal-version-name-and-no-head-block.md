# 0035 · 定稿后缀改 `_正式版`，并删掉正文头部说明块（用途 / 结构 / 图片）

- 日期：2026-10-28（同日第二次口径调整）
- 状态：**已接受**（用户指令；含既有两个功能的改名与正文清理）
- 取代 [0034](0034-final-gdd-name-and-inline-image-dir.md) 的两处：文件名后缀（`_定稿` → `_正式版`）与头部说明块（整块删除）。
  0034 的**图片落点**一条（`gdd\assets\images\`、正文相对路径、真源仍在 `evidence\`）继续有效，本 ADR 不动它
- 影响面：`skills/sr-gdd-ai`（SKILL + 模板）· `sr-gdd-fix` · `sr-gdd-review` · `sr-gdd-ue` · `sr-gdd-html` · `sr-config` · `sr-askme`（SKILL + `gdd-pipeline` / `version-history` / `gdd-writing-discipline` + 4 张教学卡）·
  `src/pure/buckets.ts` / `topic.ts` / `intake.ts` / `artifacts.ts` · 4 条纯函数用例 · `CONTEXT.md` · `cordis.patch.yml`（persona）

## 背景

用户原话：「定稿的名字还得再改一下， 改为 AI读版策划案_<功能名>_正式版.md ；正文头部说明完全删掉，模板里也删掉以后不要再出现，用途、结构、图片都是下游制作无用的信息。」

两条都是**产物形状**的收窄：

1. 定稿昨天刚改名成 `AI读版策划案_<功能名>_定稿.md`（ADR 0034），后缀与下游「正式 AI读版」的交付名（`…_正式版.md`）仍差一层：同一份东西在两个流程里叫两个名字。用户要的是**后缀就叫 `正式版`**，与下游同名同形。
2. 正文顶部的 `> **用途** / **结构** / **图片**` 三段是**写给作者自己的元信息**（这份稿干什么、章节怎么排、图从哪来），对拿稿做实现的程序 / 测试 / 配置**零信息量**，却每份定稿都占着正文最前面三行。

## 决定

1. **定稿文件名 = `AI读版策划案_<功能名>_正式版.md`**（仍在 `gdd\` 下）：
   - 历史版本 = `AI读版策划案_<功能名>_正式版_<YYYYMMDD>_<N>.md`；
   - 仍然**不带日期、不换版**（2026-10-12 的取消换版口径不变）；
   - 旧名（`AI读版策划案_<功能名>_定稿.md`、更早的 `<主题>_定稿.md`）在面板判据里继续认、归「定稿」类，**但不许新产出**。
2. **正文头部说明块整体删除**，模板里同样删掉、以后不再出现：
   - 定稿正文 = frontmatter（`doc_type` + `status`）→ `# 功能 GDD：<功能名>` → `## 1. 功能概述`，**中间不插任何 `>` 说明行**；
   - 「权威边界」不再占头部：图片角色写进 §5 的**图注**（`界面ID + 状态 + 角色`），示意值口径写在该图图注或该节范围声明里；
     "对图核对以 `evidence\` 真源为准"是**撰写纪律**，只留在 skill / 纪律文件，不进正文；
   - 模板 `feature-gdd.md` 里原有的 `> **用途** / **结构**` 两行与它们下面的 `---` 分隔线一并删除。
3. **判据跟着收紧**（否则下一次又会长回来）：
   - `sr-gdd-review` V2：frontmatter 之后只允许 H1，**任何 `>` 行出现即判不通过**；
   - `sr-gdd-fix` 复核清单：头部没有说明块（改稿时不许写回来）；
   - `sr-gdd-ai` 第 3 步完成判据：frontmatter 之后除 H1 外没有 `>` 头部说明块；
   - 纪律 D19 / D23 同步改写：D19 改为「图片角色与摆放（头部说明块已退休）」，D23 明确「H1 之后直接是 §1」。
4. **面板**：`gddKindOf` 新增 `_正式版.md` → final（`_定稿.md` 继续认作历史遗留）；`topicOf` / `deriveTopic` 的后缀表加 `正式版`（否则主题会变成"…正式版"）；「定稿」组说明改成新名。
