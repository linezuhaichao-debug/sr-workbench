# 0007 · v5：面板只留「功能卡片 + 新建功能」，决策改成一个 markdown 账本

> **取代 [ADR 0002](./0002-feature-identity-separate-from-directory-name.md)（feature_id 身份声明）
> 与 [ADR 0004](./0004-migrate-existing-data-and-merge-renamed-feature.md)（身份迁移与合并）。**
> 同时大幅收窄 ADR 0005 的范围（保留"一个功能一个工作区"与索引会话，删掉"面板发指令"那一半）。

## 背景

v4 的面板长成了三层工作面 + 五个资料页签 + 审计面 + 派生物过期检测 + 外部交付包合入 + 资产索引 + 收件箱
（`src/` 约 1.2 万行，产物 846 KB）。用户的实际用法却只有两件事：**看有哪些功能**、**新建一个功能**；
功能里的信息需求也只有三样：**头脑风暴走到哪、决策都定了什么、产物齐了没有**。

同时 v4 的决策记录被拆成"每次 Human Gate 一份 16 字段 JSON"：**只有审计能读、人读不了**，
而且它只管 Gate —— 会话里那些顺手定下来的事根本没有地方落。

## 决定

1. **面板只留两屏**：功能卡片墙（+〔＋ 新建功能〕）与功能详情（**只有三个模块**：头脑风暴 / 决策记录 / 最终产物）。
2. **目录契约从 6 桶收成 4 桶**：`source\` → `evidence\`、`delivery\` → `gdd\`；功能里只有
   `evidence\ analysis\ gdd\ decisions\`。
3. **决策记录改成一个 markdown 账本**：`decisions\决策记录.md`，条目 = **时间（年月日时分秒）+ 决策内容**，
   只在末尾追加；**所有决策**都进去（不只 Human Gate）。
4. **新建功能由面板自己建**（宿主 `uiWorkspace.createDirectory` 原语）：目录 + 4 桶 + 专属工作区 +
   预设为「策划模式」的会话；**不发指令、不写文件内容**。
5. **功能身份 = 目录名**：`feature.json` / `feature_id` 退休（见下"代价"）。

## Considered Options

- **保留 feature_id，让面板在新建时也写一份** —— 面板不能写文件内容（Remote 只有目录级操作），
  只能再挂一条"发给 agent 让它写"的指令；那正是 v4 那一整套脚手架脚本 + 回读核对的来源，与"只保留新建"矛盾。
- **保留决策 JSON，只在面板上把它渲染成时间线** —— 人读的那一面解决了，但"所有决策"仍无处落地
  （JSON 有 16 个必填字段 + status 枚举，会话里顺手定的事写不进去）。
- **把决策记录写进每个功能的 `analysis\`** —— 与"决策是定下来的事、分析是想出来的内容"这条桶判据冲突。

## Consequences

- **代价（显式接受）**：改名 = 换身份。v4 用身份声明换来的"改名不断历史"没有了；
  跨目录的合并/拆分要人工维护。真实数据里已经发生过两次改名（神话宝库 → 诸神降临、联盟悬赏 → 联盟讨伐），
  这两处**保持现状**（目录名就是现在的身份），不再提供身份层的合并。
- **代价**：旧结构里的 `source\` / `delivery\` 不会自动搬，面板把它们如实列成"不是 4 个桶的目录"，
  直到有人手工迁移（规矩见操作文档 §八）。
- **好处**：`src/` 从 1.2 万行降到约 2 千行，产物 846 KB → 179 KB；
  "新建功能"从"发指令 + 窄轮询回读 + 5 种中间态"降到 6 次本地调用。
- **好处**：决策第一次有了**人能读的形态**，而且写入时机从"Gate 之后"变成"随做随记"。
- 原先挂在 `sr-askme` 下的 `decision.schema.json` 随之删除；各 sr skill 的写入口径统一指向
  `references/decision-recording.md`。
- 保留的 v4 资产：头脑风暴四入口（指令组装一字未改）· 会话认领纪律（标题 + 面板自己写的缓存）·
  建完并入客户端 store · "读不到 / 缺件一律如实标注"的措辞纪律。
