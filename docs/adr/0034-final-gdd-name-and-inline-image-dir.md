## 背景

用户原话：「修改策划工作台输出的定稿名称，改为 AI读版策划案_[功能名]_定稿，内联的图片都放在一个gdd下新建的路径下assets\images\里。」

两条都是**产物形状**的改动，不是措辞：

1. 定稿当时叫 `gdd\<主题>_定稿.md`。它与下游「正式 AI读版」的交付名（`AI读版策划案_<功能名>_正式版.md`）
   不同名，同一份东西在两套流程里有一个半名字；用户要的是**定稿自己就叫 AI读版策划案**。
2. 图片当时有三种落法同时存在（实测）：
   - 圣物系统：`gdd\界面素材_圣物系统UE_20261013\…`（按批次建目录，12 张）；
   - 联盟讨伐：`../evidence/UE交互交付物_20260928/截图/…`（正文直接引用 evidence 真源，6 张）；
   - 另有 `gdd\界面素材_圣物系统_20261013\`、`gdd\宣讲素材_联盟讨伐_20261012\` 这些给 HTML 用的目录。
   三种都"能看"，但定稿**不能整包搬走**（相对路径跨桶），而"按批次建目录"还会随每次改稿继续增生。

## 决定

1. **定稿文件名固定为 `AI读版策划案_<功能名>_定稿.md`**（`gdd\` 下）：
   - 类型前缀 `AI读版策划案_` + 功能名 + 类型后缀 `_定稿`；
   - 历史版本 = `AI读版策划案_<功能名>_定稿_<YYYYMMDD>_<N>.md`（`version-history.md` §一 / §三 同步）；
   - 仍然**不带日期、不换版**（2026-10-12 的取消换版口径不变）。
2. **定稿正文内联的图片统一放 `<功能目录>\gdd\assets\images\`**，正文用**相对路径** `assets/images/<文件名>` 引用：
   - 这是 `gdd\` 下**唯一的图片位**：不再按批次建 `界面素材_*`，也不再直接内联 `..\evidence\…`；
   - `assets\images\` 是**正文副本**；对图核对的真源仍是 `evidence\`（D21 的两源分工一字不改），
     "§5 图为 `evidence\` 真源副本、核对以真源为准"这句话写在头部权威边界声明里，不再逐张图注重复；
   - 历史版本定稿里的旧引用**不回改**（旧目录也保留），所以任何一版历史定稿仍然打得开。
3. **面板与判据跟着改**：
   - `topicOf` 剥 `AI读版策划案_` 前缀（否则卡片与检索里多出一层"AI读版策划案"），收件箱那侧 `deriveTopic` 同改；
   - `gddKindOf` 仍按 `_定稿.md` 后缀认（新名也带这个后缀，历史遗留的老名照样归类）；
   - 「定稿」组说明改成新名 + 点出图片位；`gdd\assets\` 那层列不到文件（`load/feature.ts` 只展开一层），
     所以图片**不进产物列表、也不掉进「其它」**——这是要的行为，不是漏列。
4. **`sr-gdd-review` V1 跟着收紧**：文件名必须是新名，旧名只算历史遗留、放到报告的"历史遗留"里如实点出。
