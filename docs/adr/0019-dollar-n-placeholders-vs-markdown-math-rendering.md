# 0019 · `$n` 占位符与 Markdown 阅读器公式解析：产物保持裸写，改阅读器设置

- 日期：2026-10-15

- 相关：**0011**（追加记录判据 · 落点分账）—— 本票属"工具/环境侧"，故记在此处、不进功能决策账本
  功能侧已留指针：`features\圣物系统\decisions\决策记录.md` 2026-10-15 21:05:30

## 背景

用户打开 `features\圣物系统\gdd\圣物系统_定稿.md` 的 **Typora 阅读模式**，发现 §7 多语言文本表里
`$0` / `$1` **凭空消失**：

```
源码   | `relic_star_progress` | 第 $0 颗星：$1/5 角点亮 | $0＝当前整星序号（…）；$1＝已点亮星角数（…） |
显示   第 0颗星： 1/5 角点亮         0＝当前整星序号（…） 1＝已点亮星角数（…）
```

用户据此问「为什么多语言文本里还是有很多没有用项目的占位符 `$0`」——**把渲染丢失当成了文件里没写**。

根因：**Typora 默认开启 Inline Math**，把一对 `$` 之间的内容当 LaTeX 行内公式解析。
本机该键从未改过（`conf.default.json` / `conf.user.json` 1199 字节、2026-06-29 起未变；
`%APPDATA%\Typora\Preferences` 中无 math 相关项）⇒ 用的是默认「开」。

### 症状规律（本次实测归纳，用于反查）

Typora 的公式匹配**只在一行内做，且不认表格单元格边界**，因此**看该行 `$` 的个数奇偶**：

| `$` 个数 | 行为 | 本次案例 |
| --- | --- | --- |
| **偶数** | 两两配对；第一个 `$` 到第二个 `$` 之间的文字**连单元格分隔一起被吃掉** | §7 `relic_replace_confirm`(4) · `relic_star_progress`(4) · `relic_skill_unlock`(2) · `relic_skill_up_to`(2)；§5 UE10 / UE3 / UE6 各 2 |
| **奇数** | 末尾一个落单、无法配对 ⇒ **整行放弃解析，文字全在** | §7 `relic_draw_multi`(3) · `relic_pity_red`(3) |

> ⇒ 「有的行没事、有的行被吃」不是内容对错，是**奇偶巧合**。
> 附带假象：奇偶行里未配对的表管符会被当普通文本画出（`relic_pity_red` 那格末尾多出一个 `|`）。

## 决定

**产物里的 `$n` 一律保持裸写** —— 不加反引号（`` `$0` ``）、不转义（`\$0`）、不改写为字母记号。
阅读侧改设置：**Typora → 文件 → 偏好设置 → Markdown → 取消勾选「内联公式」**。

理由：

1. **程序侧读到的本来就是裸 `$n`** —— 运行时文本表 `PlanetRoot\Assets\HotRes\Lua\Locale\string_zh_CN.txt`
   里 **1924 行**含 `$0`、487 行含 `$1`，且 `$n` **既装数字也装名称**
   （`"领主，$0代表联盟$1邀请你加入联盟"`）⇒ 这是正式可执行文案，不是"待替换的占位符"。
2. **加反引号/反斜杠会制造新的转换面**：下游（AI 读版转置、`gtgenerator txt` 写入）拿到的是
   `` `$0` `` 或 `\$0`，都得多一步剥离，属于用一个显示问题去换一个数据问题。
3. 换阅读器/换渲染器时问题会复现，**改产物只能治本地这一台**；而这条设置是阅读者侧的开关。

## 纪律

- **凡 sr 系列产物含 `$n`，用 Typora 读之前先关「内联公式」**。
- 遇到「文件里没有 `$0`」类反馈，**先按上面的奇偶规律反查渲染**，不要改产物；
  判定顺序：① `grep '\$\d'` 看源码在不在 → ② 数该行 `$` 的奇偶 → ③ 才怀疑内容。
- 该判据**不写进功能决策账本**（对象是阅读器/环境，不是某功能的规则）；
  功能侧只留一句指针（本条右侧「相关」已给）。

## 影响

- 受影响面：所有含 `$n` 的交付文档（定稿 §7 / §5、成稿、宣讲稿 HTML 不受影响——浏览器不解析 LaTeX）。
- 本次实例：`圣物系统_定稿.md` 保持 701 行 / 68,511 字节、`status: active`，**本项零改动**；
  §7 全表 **50 行 × 9 列零结构异常**（"多出来的 `|`" 已核实为渲染假象）。
- 工具侧可选补强（未做，待需要时）：在含 `$n` 的产物头部或 §7 表下加一句
  「文中 `$n` 为运行时占位符，阅读器若开内联公式会吞掉」——**当前不加**，避免定稿多出说明块。
