# 0022 · `sr-gdd-ue` 不再自建素材目录：图片只取已经存在的目录

- 日期：2026-10-16
- 状态：**已接受**（用户选 B 方案：删默认值，与 `/sr-gdd-html` 对齐）
- 相关：**0020**（两源分工 · 真源只有一个）· **0016**（UE 只写交互的 lint）· 纪律 **D19**（本轮同改）
  变更落在 `sr-gdd-ue/SKILL.md`（输入项 + 第 3 步）与 `sr-askme/references/gdd-writing-discipline.md` 的 D19

## 背景

2026-10-16 用户问：`/sr-gdd-ue` 为什么还要在功能目录的 `gdd\` 下建「界面素材\_<主题>\_<日期>\\」，
不能像 `/sr-gdd-html` 一样直接用 `evidence\` 里的？

查证结果（实测，不是推断）：

| 查证项 | 结果 |
| --- | --- |
| 直接用证据有没有先例 | **有**。联盟讨伐定稿 §5 图注就是 `../evidence/UE交互交付物_20260928/截图/01_活动界面_常规难度.png` |
| 圣物系统为什么没用真源 | 真源 `evidence\MN boss活动\` 分 `MN boss活动-1\`、`MN boss活动-2\` 两批；两批都从 `01_` 起编号；顺序是导出批次序 —— 三条都撞生成器约束 |
| 生成器的三条约束 | `gen_01.py:128` 的 `--img-dir` **单值且必填**（装不下两个子目录）；`content.json.image` 按文件名**一一对应**（两个 `01_` 互相顶）；逐界面节按**玩家流程顺序**排（批次序不是流程序） |
| 那份副本到底是什么 | 12 张里 6 张与真源同名同字节，另 6 张**改名后仍同字节**（sha256 实测），新画的素材 **0 张** |
| 默认值的来路 | `sr-gdd-ue` 2026-10-13 拆分提交 **88bf79a** 一次写入 `SKILL.md:126`，依据是**圣物系统那一次的实操目录** |
| `sr-gdd-html` 有没有这个默认 | **从来没有**（`git log -S '界面素材' -- skills/sr-gdd-html/SKILL.md` 零命中）—— 它只问「界面图目录」 |

即：**默认动作（先造副本）与 ADR 0020 / 纪律 D21 的口径（真源只有一个 = `evidence\`）方向相反**，
且把一个一次性做法固化成了常规动作。

## 决定

`sr-gdd-ue` 第 3 步的默认素材目录**删除**，与 `/sr-gdd-html` 对齐：

1. **图片只有一个来源：已经存在的目录** —— 用户指的目录，或定稿 §5 图注已经指向的那个（通常是 `evidence\…` 真源；两者不一致时以用户为准）；
2. **不新建素材目录**：没有可用目录时不凑合，缺图界面走 `guide` 指路占位框；
3. **真源不能直接当目录用时先报告、由用户定**：把三条约束讲清（跨批次子目录 / 批内重名 / 顺序不是流程序），给两个选择 —— 换一个已经备好的目录，或**用户明确同意后**才落副本；
4. 术语与 `/sr-gdd-html` 统一为「**界面图目录**」。命令行参数 `--img-dir` 与工具 help 里的「截图目录」保持原样（那是工具自己的词，改了会与内置工具包 sha256 校验冲突）。

同轮收敛纪律 **D19**：原句「图片资产放功能目录下的固定位置并给清单」没说清真源与副本的关系，
与 D21「真源只有一个」并列时读不出谁优先。改为 —— 优先 `evidence\` 真源、§5 图注指向它；
确有 `gdd\` 下副本时注明「副本 · 真源见 `evidence\…`」，副本**只作正文引用、不作对图核对的依据**；
D19 原有的「每张图在图注写 `界面ID + 状态`，并声明角色」保留。
