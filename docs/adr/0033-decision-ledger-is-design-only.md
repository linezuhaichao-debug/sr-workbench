# ADR 0033 · 决策记录只记设计口径，流程与执行不进账本

- 状态：已采纳（2026-10-27）
- 影响面：
  - `sr-workbench\cordis.patch.yml`（persona「决策记录契约」新增一节「只记设计」）
  - `sr-workbench\skills\sr-gdd-fix\SKILL.md`（第 6 步 Human Gate 的记录条款）
  - `sr-workbench\skills\sr-gdd-review\SKILL.md`（第 5 步「审查结论本身是一条决策」改为不记）

## 背景

圣物系统的 `decisions\决策记录.md` 到 2026-10-27 已经 **113 条 / 602 行 / 174 KB**，里面真正是
设计口径的只有 34 条。其余是门通过（approve / revise）、审查结论、文档结构与列宽瘦身、
模板迁移、skill 与脚本改动、文件落点与部署、AI 读版台账签收、冲突后重建、验收读数。

根因不在"忘了分账"，而在**三处规则都在鼓励记账**：
persona 的「什么时候记」写「只要定下了一件事就记」、
`sr-gdd-fix` 写「用户选择后追加一条：决策写这次拍板（approve / revise / reject）」、
`sr-gdd-review` 写「审查结论本身是一条决策，追加一条」。
三条加起来，等于要求把**流程事件**也写进设计台账。

## 决定

1. 判据换成一句问句：**"这条是给玩家 / 程序看的设计决定吗？"** 是 → 决策记录；不是 → ADR，或不记。
2. 明确**不进**清单：门结果与流程、执行记录与读数、文档结构与格式、模板 / skill / 脚本 / 引擎改动、
   文件落点与命名与部署、收材料与比对过程。
3. 明确**进**清单：规则与分支、数值与公式、分类属性枚举、命名与术语、内容取舍与范围门、
   界面构成与按钮文案、配置契约里字段与本功能数据的对应、明确"本版本不做"的边界。
4. `**决策**` 行写口径本身，不写"我做了什么"。
5. 清理旧条目用**归档**：归档文件**不放 `decisions\`**（那里只有一个决策文件）。

## 后果

- 圣物系统账本清到 **34 条 / 190 行 / 45 KB**；被移出的 79 条原样归档到
  `%TEMP%\sr\圣物系统\决策记录_归档_20261027_流程与执行留痕.md`（未删除）。
- 新会话起，门通过 / 审查结论不再进决策记录 —— 报告与 ADR 各自承载。
- 代价：想知道"这一稿什么时候过的门、复审结论是什么"，要去读审查报告与 ADR，账本里查不到。
  这是用户明确要的取舍：**账本只回答"设计为什么这么定"**。
