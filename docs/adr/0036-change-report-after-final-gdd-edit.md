# ADR 0036 · 定稿改完必须当场给出「改前 → 改后」对照

- 状态：已采纳（2026-10-30）
- 影响面：
  - `sr-workbench\skills\sr-gdd-fix\SKILL.md`（功能说明加一条；第 2 步措辞；新增第 6 步「出改动对照」；原 Human Gate 顺延为第 7 步；产出规范加一行）
  - `sr-workbench\skills\sr-config\SKILL.md`（第 5 步加「改完当场给改前 → 改后对照」与相应完成判据）
  - `sr-workbench\skills\sr-gtgenerator\SKILL.md`（结果汇报模板加「规模对比」块与对照成对要求；硬规则加第 8 条）

## 背景

2026-10-30 的圣物系统一轮里，定稿按 24 条体检缺口改了 **62 处变更块**，用户拿到的是「改完了 + 结论」，
第二天追问「说明一下定稿这次修改了哪里，从什么改成什么」才补出对照表。

原 skill 其实要求过两次：

- 第 2 步产出**改动清单**（表头就有「改前 / 改后」列）；
- 第 6 步 Human Gate 写「向用户呈现**改动清单（改前 → 改后）**+ 改后的受影响章节」。

两条都不足以保证它真的被交出来，原因是三个：

1. **改动清单是「计划」不是「实际」**：它是第 2 步写的，改完没跟实际 diff 对账，
   照着它念会把「顺手修的（断行、旧数字、指代错误）」漏掉——本轮就漏了 7 处字段名进 §5 的自查修正。
2. **「呈现」和「过门」绑在一起**：门是可选的等待动作，用户没表态时，呈现就容易被一句
   「改完了，你批」带过去；本轮我直接跑复审、同步下游包，门压根没过，对照自然没给。
3. **没有硬判据**：「呈现」没有完成判据可核，也没有规定基准是谁——凭记忆列也能算「呈现过」。

## 决定

1. 把「出改动对照」从 Human Gate 里**拆成独立一步**（第 6 步），Human Gate 顺延为第 7 步。
2. **基准固定**：与第 4 步动笔前留的**历史版本**逐行 diff（`git diff --no-index` / `difflib` / `Compare-Object`），
   `改前` 列**照抄原文片段**，不许概括成「原口径」。
3. **位置精确到条目**：`§4 R4「升星消耗」` / `§5.6 UE6` / `§6.1 cost` / `§7 relic_new` / `AC8`；只写章节号不算。
4. **按章分组 + 组末统计**：规则层（§4）/ 界面层（§5）/ 契约与文本（§6·§7）/ 范围门·验收·交接（§8·§10·§11）。
5. **计划与实际对账**：第 2 步清单是「打算改什么」，第 6 步是「实际改成了什么」，多出来 / 砍掉 / 换做法的逐条给原因；
   顺手修的单列。
6. **数字只来自 diff**：没跑 diff 不许写「改了 N 处」。
7. **不落盘**：对照表是对话里的一次性交付，落盘的仍是决策记录与审查报告。
8. 完成判据：**不许出现「diff 里有、表里没有」的变更**；多条合并成一行要注明合并了哪几处。

## 后果

- 用户不必再问「改了什么」；一轮改动的可信度由**可复现的 diff** 背书，而不是我的自述。
- 顺带把「门可跳过」这一漏洞显性化：第 6 步的完成判据先于第 7 步，对照表没发就进不了门。
- 代价：每次改稿多一次 diff 与一张表（本轮 62 行 → 约 5 张分组表）。相对「用户次日追问再补」，
  这个成本可以接受。
- 与 ADR 0033 不冲突：对照表不落盘、不进决策记录，账本仍然只记设计口径。

## 推广（同日追加）

同一条判据在另外两个「会改真实数据」的 skill 上也成立，2026-10-30 一并落地：

| skill | 落点 | 与 sr-gdd-fix 的差别 |
| --- | --- | --- |
| `sr-config` | 第 5 步「写入与读回」新增**改完当场给「改前 → 改后」对照**（位置 / 改前 / 改后 / 依据），完成判据加「对照表与 `plan.json` 的 op 一一对上，不许出现 plan 里有、表里没有的 op」 | 它有天然的基准：`plan.json` 的 `expect_before` + 读回值，**不需要跑 diff**——改前改后都是机器给的，比 GDD 那份更难造假 |
| `sr-gtgenerator` | 结果汇报模板加 **【规模对比】**（条目数 / `Export=true` 条数 / 导出行数 的前后值 + 落表前查重 total），并规定新增给「落表前 total + 落表后读回」、修改给 `txt get` 快照原文、废弃给 `Export true → false`；硬规则加第 8 条「汇报不许只报已完成」 | 它原本已有【修改对比】【废弃对比】，缺的是**数量级证据**与「不许只报完成」的硬约束；新增（A1/B1）本来没有「改前」，用查重结果与规模对比补位 |

为什么三处都要：这三条路的共同失败模式是一样的——**用户看到的是「改完了 / 已 PASS」，
而实际差异留在了引擎日志和 diff 里**。判据统一成「改前 → 改后 + 数字来自工具输出」之后，
用户不必再追问一次，也不用相信我的自述。

不复制的部分：具体列名与格式各 skill 按自己的数据形态定（GDD 是条目与原文片段、配置表是单元格与
`expect_before`、GTGenerator 是键值与条目数），**只统一"必须给、必须成对、数字不许估"这三条**。
