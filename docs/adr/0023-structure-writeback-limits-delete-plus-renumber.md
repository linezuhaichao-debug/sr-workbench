# 0023 · 结构类写回的能力边界：删一个规则组 + 整体重编号，无法绑定 structure_plan

- 日期：2026-10-16
- 状态：**已接受**（本轮按此执行；属工具/流程侧结论，功能侧只留指针）
- 相关：`references/continuous-writeback.md` §Structure Writeback (Batch A/B3) · `scripts/verify_structure_restructure.py`
  功能侧指针：`features\联盟讨伐\decisions\决策记录.md` 2026-10-16 的「完全跟随定稿重排」与「删除内容变化组」两条

## 背景

联盟讨伐写回事件 `WB-20261016-001`（2026-10-16）里，策划拍板把正式 AI读版的规则组**完全跟随定稿**重排：
「BOSS 形态」由末组（原 R13）上移到第 2 组、后续组号整体顺移、界面与交互单列为 R13（原 R14），
同时**删除**原 R12「内容变化」规则组。按该技能的自然语言契约，这属于结构类改动
（"chapter reordering, renumbering"），"must carry a `structure_plan` extension binding"。

实跑工具后确认三件事（全部为脚本输出，非模型判断）：

1. `detect_structure_change(baseline, candidate)` = **False**。它的判据是：
   两稿规则编号个数相同且序列不同 → True；否则取共享编号集合，
   若共享编号在**两稿中的出现顺序**不同 → True；再看「无编号 H2 正文」的次序。
   本轮共有编号 R1–R13 在两稿中**同为升序**（只是各自所指的组换了），
   编号个数 14 vs 13 不相等，H2 次序未变 ⇒ 三项都不命中，门不阻断。
2. `verify_structure_restructure` **无法表达「删除一个规则组」**：它要求基线的每个章节在候选稿有对应
   （`moves` 的目标必须存在且正文逐字一致，未声明的基线章节消失即报错），
   而 `moves` 又要求搬移章节正文在应用编号映射后逐字一致 ⇒ 删除章无论如何都过不去。
3. 该工具的重编号引用核对用的是**朴素 token 映射** `\bR\d+(\.\d+)?\b` 全量替换。
   本轮三处写法是**范围**（`R1–R13` 表示"全部规则组"，语义上新值应为 `R1–R12`），
   朴素映射会把它变成 `R1–R2` ⇒ 即使只做重编号，绑定后也必然报"引用与声明不符"。
   另外正式版界面与交互导语里的「交互终稿 R7 / 2026-09-28」是**交互交付物修订号**，
   不是规则编号，朴素映射会把它错改成 R8。

⇒ 结论：在这一轮的真实形态下，「绑定结构方案」既非门所要求，又必然 FAIL；「不绑定」是唯一可行路径。

## 决定

结构类写回按**门所判**执行，不按自然语言契约的字面自行加码：

- **门的判定即权威**：`detect_structure_change` 返回 False 时不绑定 `extensions.structure_plan`，
  改按普通语义写回处理；结构改动本身用 `changes[]`（`change_type: modify/delete`）逐条声明，
  并在 `差异回写审核摘要` 里用一节「结构类改动的路由说明」向策划暴露。
- **不为了"能绑定"而改产物**：不把删除写成空壳章节、不把范围写法降级成朴素映射能接受的形式
  （那等于用一份更差的正式版去迁就校验器）。
- **留痕三处**：事件 `extensions.structure_change_routing`（含门输出与理由）、写回输入记录、
  差异回写审核摘要（策划可见）。搬移保真由独立机械比对证明：
  11 个搬移组在应用编号映射后**逐字一致**，2 个组只含声明的语义改动。

## 纪律

- 遇到结构类写回，**先跑门**（`detect_structure_change`）再决定是否绑结构方案；
  不要凭"这看起来是结构变更"直接绑、也不要凭"门没报"就当作没有结构改动。
- 绑结构方案之前先确认三件事：① 没有删除章节；② 搬移章节正文确实逐字保留；
  ③ 全文没有**范围写法**的编号引用与**同名不同义**的编号（如交付物修订号 `R7`）。
  三者任一不成立，就不要绑，走语义写回 + 摘要留痕。
- 编号引用同步**必须按语义改**（`R1–R13`→`R1–R12`），不许机械替换；
  交付物修订号之类的同名 token 要显式排除并留痕说明。

## 影响

- 本轮实例：`WB-20261016-001` 未绑定 `structure_plan`，`--validation-scope writeback` = `PASS_WITH_WARNINGS`（0 ERROR）；
  结构改动以 CHG-002（重排/重编号）与 CHG-003（删除规则组）两条进入事件与摘要，签收要求 `summary_and_snapshot`（与 deletion 类无关的独立结论一致）。
- 工具侧待办（**未做，待真实需求**）：① `detect_structure_change` 是否应把"编号个数不等 + 共享编号升序但所指改变"也判为结构变化；
  ② `verify_structure_restructure` 是否需要支持"章节删除"（`moves` 允许 `new_title: null` 或单独的 `deletions[]`）；
  ③ 引用核对是否需要 range-aware 与显式白名单（交付物修订号）。按"反膨胀"纪律先记录、不改工具。
