# 0038 · 工作会话不再写死标题：名字交给 DSH 按工作内容自动生成

> 触发（2026-11-17 用户原话）：「**从策划工作台新建会话的会话名字能不能不要生成固定的名字，
> 我希望还是让你帮我自动根据工作内容生成会话名字**，我还开着」。

## 背景

从 [ADR 0014](./0014-new-session-button-creates-and-takes-over.md) 起，面板每造一条工作会话都会
`session.rename("策划工作台·工作（<主题>）")`；[ADR 0015](./0015-one-session-per-dispatch.md) 改成
"一次派活一条"之后，同一个功能下会堆出**一串同名会话**（那条 ADR 明码标价的代价）。

这个标题当初有两个用途：① 人一眼看出这是哪个功能的活；② **认领凭据** —— 清缓存之后靠标题前缀
认回"这条是我造的"（`pure/leftovers.ts`）。

但 DSH 的会话标题是这样的（`dsh-session-title`，本机 profile 装了
`@deepseek-ai/dsh-experimental-session-titles-bundle`）：

- 三个来源，**最新者胜出**：内置回退（第一条用户消息的前若干词）/ 自动生成提供方（LLM，按会话内容）/
  显式 `rename`（用户来源）；
- **用户来源的标题会钉住会话** —— `scheduleForUserMessage` 里那句
  `if (this.get(session)?.source.kind === 'user') return`：之后来的用户消息**不再安排自动修订**，
  只有显式 `refresh()` 才是解钉手段。

⇒ 面板那一次 `rename`，等于把这条会话的名字**永久钉死**在"策划工作台·工作（X）"上：
本机明明挂着按内容起名的提供方（实测别的会话都拿到了「圣物技能新增六级ID」这种标题），
工作会话却永远是那一句。

## 决定

1. **工作会话一律不 `rename`**：〔新建会话〕、四入口派活、新建功能三条路都走同一个
   `createSessionAt(root, title, …)`，现在统一传**空标题**（函数照旧保留 `title` 参数给索引会话）。
2. **名字交给 DSH**：第一条用户消息之后，内置回退先给一个，随后提供方按会话内容生成
   （四入口那条指令的第一行就写着入口与主题，`pure/intake.ts`，名字不会跑偏）。
3. **索引会话保留固定标题** `策划工作台·索引（<工作区名>）`：它是面板的读通道、会被反复发指令，
   名字稳定比好看重要；而且它不是用户点出来的那个"新建会话"。
4. **认领凭据换掉**：新增 `localStorage['sr-wb.mine.v1']`（`pure/sessionpick.ts` 的
   `mineCacheKey/Parse/Add`）记录"面板亲手建过哪些会话"；`pure/leftovers.ts` 认领改成
   **id 在这张表里**（新会话）**或标题是旧形状**（旧版本建的会话）**且** cwd 落在
   `<SR 工作区>\features\<主题>` 这一层。
   ⇒ 旧口径不丢：清缓存 / 换浏览器后，旧会话照样靠标题认；新会话靠本地账本认，清掉就**不认**
   （宁可少清，也不要认错人的对话）。
5. **主题一律按 cwd 取**（`featureTopicOfPath`），不再从标题反推 —— 标题可以被手抄、路径不会；
   顺带修掉"标题写 A、cwd 是 B 时判错功能"的隐患。
6. 刚建出来的会话**还没有名字**（第一条消息之后才有）⇒ 界面必须当场说清，否则像"漏了起名"：
   〔新建会话〕的提示改成"名字先空着：你在这条会话里说的第一件事（或下一次派活）会让 DSH 按内容自动起名"。

## Considered Options

- **保留固定标题、只去掉序号 / 换个更细的名字**：否 —— 只要 `rename` 过就还是钉死的，用户要的是名字跟着活走。
- **面板自己调一次模型起名再 `rename`**：否 —— 多一次调用与延迟，而且 `rename` 之后仍然钉死
  （后续消息不再修订）；"按内容和消息修订"正是 DSH 内置那条提供方在做的事。
- **只改〔新建会话〕、四入口照旧写死**：否 —— 两条路造的是同一类会话，两种命名会让侧边栏看起来像两套东西；
  而且四入口正是"一堆同名会话"的主要来源。
- **标题 = 固定前缀 + 内容**（`策划工作台·工作（联盟讨伐）·数值梳理`）：否 —— 用户口径原话是"不要生成固定的名字"。
- **索引会话也交给自动标题**：否 —— 它随时可能被面板发指令（配置写入等），名字会跟着乱跳；机器通道稳定优先。
- **干脆不做残留清理**：否 —— 用户 2026-10-13 明确要求过"我手动删了功能，这个没有清理吗"（ADR 0013）。

## Consequences

- 侧边栏不再出现"策划工作台·工作（X）"；同功能的多条会话靠**内容名**区分（比同名的更好认）。
- **刚建出来时没有名字**（侧边栏显示默认名），发出第一条指令后由 DSH 起名；这条降级已在界面上说明。
- 残留清理的覆盖面变了：靠本地账本认新会话 —— **清掉 localStorage / 换浏览器 / 换机器**之后，
  那些会话清不掉（旧标题那份凭据仍能认旧版本建的）。这条如实记：宁可少清，也不要处置用户的对话。
- `workTitleFor` / `WORK_TITLE` / `pickWorkSession` 在生产侧都不再有调用方（`pickWorkSession` 自
  ADR 0015 起就没有），保留它们只为**认旧会话**与用例；清理留给下一次死代码票。
- 判据（这一轮新增/改动的用例）：
  · `test/create-flow.test.ts`：新建功能与〔新建会话〕**不改名**（且索引会话仍改名）；`r.title === ""`。
  · `test/panel-view-timing.test.ts`：〔新建会话〕不改名；"有降级不切走"那条的降级源从"改名失败"
    换成"工作区登记被拒"（同样是**有后果**的降级）。
  · `test/pure-leftovers.test.ts`：按 id 表认领 / `mine` 拿不到时只认旧标题 / 主题按 cwd 取。
  · `test/pure-sessionpick.test.ts`：`mineCache` 的坏值、去重、上限。
- 未做：标题提供方的长度参数（`targetCjkCharacters: 10` 等）不在本仓 —— 想让名字更长/更短，改 profile 里
  `@deepseek-ai/dsh-experimental-session-titles-bundle` 的 patch。
