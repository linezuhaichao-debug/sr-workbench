# 0012 · 可选步骤必须呈门，且说明文档分层

> 触发：2026-10-13「圣物系统」成稿门通过后，会话只提了「配置表 `/sr-config`」这一项，**没提「线框图替换 ASCII」**。
> 用户追问后暴露两件事：① 这条可选项在 agent 会读的流程文件里**没有落点**；② 修它时，我把执行细则写进了**给用户看**的 `使用说明.md`。

## 背景

- SR 主线的第 3 步是「**配置与线框图**（可选）」—— **两件事**。全仓核查：这一步**只写在 `skills/sr-askme/references/使用说明.md` 第 11–13 行**（给人看的主线图），**没有任何 skill 的 SKILL.md 提到它**；各 skill 里出现的"线框图"都是别的意思（D5/D12 要求 GDD §5 必须有 ASCII 线框图；`sr-gdd-html` 把 ASCII 原样贴进宣讲页；`sr-gdd-ue` 第 127 行更明确："定稿里只有 ASCII 线框图时按『无图』处理，**按原样搬**，不要重画"）。各门只规定四 / 五个选项，**没有任何门规定"呈门时要提示可选下一步"** ⇒ 这条可选项天然从流程里消失。
- 这条路本身还是**断的**：`使用说明.md` 原写「可人工调用 figmaMCP 生成」，而工作区 `AGENTS.md` 明确 `sr-figma-design-system` 技能 **2026-10-09 已删除、不要再路由**。
- 会话侧的实际漏项：成稿门后是**凭记忆组的选项**（"先对齐配置表再出定稿 / 跳过 / 先定 OQ1"），只覆盖了配置表那一半 —— 不是"文档没写所以不知道"，而是没有照主线图逐项念。

## 决定

1. **呈门必须逐项念主线的可选下一步**：`sr-gdd-human` 第 5 步（成稿门）与 `sr-gdd-ai` 第 6 步（定稿门）各补一段「呈门时必须逐项念主线的可选下一步（配置表 / 线框图）」—— **"可选"不等于可以不提**；只提一项、或凭记忆组选项而漏掉另一项，都算本步没做完。
2. **线框图这一项的现状写准**：**没有对应技能**；figma 相关技能已删除，需**人工出图**或先挂 figma MCP；替换 UI 可能带来功能改动 ⇒ 改完要落回 GDD（走 `/sr-gdd-fix`，按其影响面闭合规则扫 界面 ↔ 规则 ↔ 验收 ↔ 多语言）。
3. **文档分层**：面向用户的 `使用说明.md` **只画主线、不写执行细则**（不带"必须 / 不许 / 影响面闭合"这类 agent 约束）；执行约束写进对应 skill 的步骤。`使用说明.md` 里那句过时的 figma 指引改为「（没有对应技能，人工做）」。
4. **教学快照同步**：改 `使用说明.md` 后必须重跑 `npm run gen:teaching`；`check:teaching` 判定「快照 == md 整份字节」，忘跑就红。

## Considered Options

- **只在 `使用说明.md` 里加重语气**：否 —— 它是给人看的主线图，agent 不会被它约束；而且越长越没人读。
- **给线框图补一个新 skill**：暂不 —— 图是人工 / figma 产物，先靠「呈门必提 + `/sr-gdd-fix` 回写」这条链走通；将来真要做成 skill 再立票。
- **执行细则进本 ADR、用户文档保持两行短句**：采纳（第 3 条）。

## Consequences

- 两个 GDD skill 的呈门步骤自此含该提示；`使用说明.md` 回到两行短句（4044 → 3731 字节，减少量只来自 figma 那处保鲜）。
- **教训入档**：可选项若只写在"给人看的主线图"里，就会从 agent 的流程里消失 —— **凡是 agent 必须做的事，都要有一条落在它真会读的流程文件里**。
- 与之配套的记账纪律见 [ADR 0011](./0011-append-record-criteria.md)：功能账本只收"对象是本功能"的决策，工具 / 流程 / 文档类决策进 ADR。
- 遗留：线框图仍待人工出图；出图后按 `/sr-gdd-fix` 回写定稿 §5（实例见 `features\圣物系统`）。
