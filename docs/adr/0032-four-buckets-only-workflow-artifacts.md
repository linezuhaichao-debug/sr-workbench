# ADR 0032 · 四个桶只收策划工作流的产物，脚手放 TEMP

- 状态：已采纳（2026-10-27）
- 影响面：`sr-workbench\cordis.patch.yml` 的「工作台契约 · 一个功能 = 一个目录」一节

## 背景

四个桶的判据原本只写「谁产生 / 给谁看」，没有写**什么不许进**。结果是每轮任务里
**干活的脚手架**被当成产物塞进了桶：探查配置表的临时 dump（`_probe_*.txt` / `_diff_*.txt`）、
一次性生成计划的脚本（`_gen_*.py`）、校验用 CSV/JSON、回答页的渲染草稿（`_am_*.md`）。
圣物系统一个功能目录里就攒了 22 个这样的临时件，另有 4 份审查报告的历史版本副本
（而口径是审查报告**不存历史版本**）。桶因此失去了「打开就知道有哪些产物」的作用。

## 决定

在「工作台契约」下新增一节「桶里只放策划工作流的产物（硬规则）」：

1. 每个桶列出**允许的产物类型**（evidence = 进来的原件；analysis = 头脑风暴 / 分析产出；
   gdd = 正文与流程产物；decisions = 只有决策记录）；
2. **禁止新建第五个桶**（`_work\` / `tmp\` / `draft\` 之类）；
3. 临时件一律放 `$env:TEMP\sr\<功能名>\`，任务结束前清掉；
4. 两条判据：**说得出来才算数**（能一句话说出它是哪份产物的哪一步）、
   **明天的读者会引用它才算数**；拿不准时问「这是交付物还是脚手」。

## 理由

原来的判据是**正向的**（"这是什么"），对临时件没有约束力 —— 临时件总能找到一个
勉强的桶（探查输出像分析、草稿像正文）。改成**反向禁止 + 指定落点**（TEMP）才有可执行性，
而且 TEMP 零成本、不影响功能目录的整洁。

## 后果

- 新会话起生效（persona 在会话开始时注入；本会话已加载的 persona 不回溯）。
- 圣物系统当前目录已按新规则清理：22 个临时件 + 4 份审查历史版本移到
  `$env:TEMP\sr\圣物系统\`（未删除，可回收）。
- 仍待用户裁决：`features\圣物系统\gdd\A002-货物道具表.xlsm` 与它的 `.backup.` 是运行时配置表的
  旧副本，按新规则也不算工作流产物，但删/移会影响历史报告的取证路径。
