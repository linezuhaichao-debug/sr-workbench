# 界面 UE 规则 HTML 工作流（SR-GDD-UE）

## 功能说明

**唯一输出：界面 UE 规则 HTML（单文件自包含）**。把一份功能 GDD **定稿**（`<功能目录>\gdd\<主题>_定稿.md`；`sr-gdd-ai` 主线 `active` 定稿，`provisional` 工作版亦可）里的 **§5 用户体验与界面流程**整节抽出来，重排成"能边看图边对着做界面"的单页 HTML：按玩家流程逐界面一节、左栏完整界面截图、右栏逐控件 UE 规则块，截图 base64 内嵌、无任何外部依赖，可直接投屏、可直接外发给 UE/UI 同事。

**受众是 UE/UI 同事**：他们要的是"这个界面长什么样、每个控件什么行为"，不是功能规则、配置契约与验收标准。所以本 skill **只出 §5**：

| 定稿章节 | 本 skill |
| --- | --- |
| §5.0 界面清单总览（含进入 / 退出方式） | **出** |
| §5.1–§5.N 逐界面（线框图 + UE 规则表） | **出** |
| §5 末 界面流程（text）/ 状态机（如适用）/ 全局交互规范 | **出** |
| §1 功能概述 · §2 本功能不解决什么 · §3 核心循环 · §4 功能规则 | 不出 |
| §6 配置契约 · §7 多语言文本 · §8 范围门 · §9 埋点信号 · §10 验收标准 · §11 交接清单 | 不出 |

一句话分工：**要"只讲界面"给 UE/UI 同事 → 本 skill（`_UE.html`）；要"定稿全貌一条不漏、给人读" → `/sr-gdd-html`（`_宣讲.html`）；要改定稿内容 → `/sr-gdd-fix`。**

渲染规格与 AI_SR 交互交付的 `01_宣讲会交付.html` 同源：固定验收模板见 `resources/toolkit/01_宣讲会模板.md`，通用生成器见 `resources/toolkit/生成脚本/gen_01.py`（原样内置，无第三方依赖，Python 3.8+）。

**本 skill 不生产设计结论**。它只做呈现层的重排——界面、控件、UE 规则全部来自源定稿 §5；源定稿 §5 没写的一律标"待定"，不替策划补规则、不臆造交互。**只接定稿**：还没有定稿时走 `sr-gdd-human`（写成稿）→ `/sr-config`（落配置）→ `sr-gdd-ai`（整合定稿）。

### 参考优先级（不要自由发挥结构）

1. `resources/toolkit/01_宣讲会模板.md`（固定验收模板，内容边界与页面结构的唯一权威）
2. 用户当轮指定的参考样式
3. 两者皆无时：`examples/合成示例/01_界面UE规则_示例.html`（形态基准）

排版间距/字号等视觉参数模板**不设死**，但结构、内容边界、图片承载方式不得改。

### 内容红线（越线即返工）

- **只放最终规则**：定稿口吻的界面状态、控件行为与交互反馈；
- **禁止过程性信息**：确认编号（Q1/Q2…）、用户原话、"拍板 / 已确认 / 跟推荐"等过程措辞一律不出现——这些属于决策记录与 GDD 的职责，不属于给 UE 同事看的界面稿；
- **不放文本 ID 清单**（那是交互回写文档的职责）；
- **不放非界面内容**：功能概述、本功能不解决什么、核心循环、功能规则、配置契约、多语言文本、范围门、埋点、验收标准、交接清单——一句都不进（这是本 skill 与 `/sr-gdd-html` 的分界线，越线即返工）；
- 每个界面章节是"讲这个界面"的最小完整单元：**UE 同事只看本节即可开工**；
- **不残留**：`content.json` 是**当前定稿 §5** 的完全派生物——定稿删掉的界面、控件与文案不许留在稿子里；判据是 `../sr-gdd-html/tools/orphan_check.py --content --section 5`（见第 4 步）。

### 图片红线

- 图片一律 `data:image/...;base64,` 内嵌，保证单文件可独立打开、单独发送不丢图；
- **禁** `https://` 外链图（会过期、离线丢失）；
- **禁** `./assets/` 等散装资源目录——"HTML + 资源目录"没有例外，需要连目录才能打开的稿子只能算非正式过程文档；
- 图外标注（字母/引线）**默认关闭**，未获当轮明确要求时交付干净原图；启用时按 `resources/toolkit/双栏版式参考_outside-callout-module.md` 执行（含 `#F02864` / 2px / 实线 / 禁斜线等细则）。

## 使用方法

本 skill 是**用户调用型**（frontmatter `disable-model-invocation: true`）：只能由人输入 `/sr-gdd-ue` 触发，agent 不会自动接手，也不进入面向模型的技能目录。

```
/sr-gdd-ue <定稿路径或主题>
```

例如"把《英雄升级功能优化_定稿》的界面部分出成给 UE 看的 HTML"、"这份定稿出一版界面规则图册"。

## 无输入时的行为

裸调用纪律见 `../sr-askme/references/bare-invocation.md`。本 skill 收集：

1. **源定稿**：要出 HTML 的那份**定稿** md（路径，或主题名由我从**本功能目录的 `gdd\`** 下定位 `_定稿.md`）；
2. **界面范围**（可选，默认按定稿 §5 界面清单全出）：本次只出哪几个界面/状态；
3. **截图目录**（可选，没有就说没有，无图界面走指路占位框，不阻塞）。

用户补齐后再从第 0 步开始。

**输入守卫**：源文件不是**定稿**时停下，说明本 skill 只接功能 GDD 定稿，并指出该走哪一步——还没有定稿：`/sr-gdd-human` → `/sr-config` → `/sr-gdd-ai`；已有定稿但要改内容：`/sr-gdd-fix`。**不静默加工非定稿材料**——成稿、体验报告、复刻规格、评审意见、会议纪要等一律不做。

## 路径约定

`<SR_WORKSPACE>` / `<SR_PROJECT>` 取自 `%USERPROFILE%\.dsh\sr-workbench\config.local.json`；字段缺失、为空或路径失效时运行 `/sr-askme` 补齐；成组安装见 `../sr-askme/SKILL.md` §四。

本 skill 自身资源以**相对路径**引用（`resources/toolkit/...`、`tools/lint_content.py`），保证 skill 目录可整体搬迁。

## 执行流程

### 第 0 步 · 载入项目语境

读 `../sr-askme/references/sr_project_context.md`，遵守其中的数值铁律与写作约束（中文、术语与项目代码命名一致、gdd 不出现代码/技术选型细节、区分 RPG 战斗与 SLG 战斗）。

数值铁律在本 skill 下的执行方式：**界面稿沿用源定稿的数值口径**——源定稿写"参考值 X，待定"的照写，写 `配表名.字段名` 的照写；本 skill 不新增、不换算、不补全任何数值。
完成判据：页内每个数值都能在源定稿中找到同一写法——不新增、不换算、不补全。

### 第 1 步 · 输入确认

定位源定稿，先读头部 `doc_type` + `status`：须为 `doc_type: final_gdd`，其中 `active` 按正常出稿流程处理；`provisional` 允许继续抽取，但 `content.json` 的 `footer` 必须显式写"工作版，非正式定稿"；`blocked` 直接停止并报告阻断原因；`pending` 说明定稿还没过门，建议先走 `/sr-gdd-review`；**其余情况**（`doc_type: draft_gdd`、无头部字段的旧文档）说明这不是可出稿的定稿，按「输入守卫」停下并给出去路，不据文件名猜测。随后确认三件事，缺一即问用户，不自行假设：

| 项 | 内容 |
| --- | --- |
| 源文件 | **定稿**路径 + 版本/日期（同名多版本时以用户指定为准，不默认取最新） |
| 界面范围 | 全量界面，还是本次只出某几个界面/状态 |
| 截图目录 | 有无现成界面图；没有则确认走指路占位框 |

同时清点源定稿 **§5** 的可用结构：§5.0 界面清单总览、§5.1–§5.N 逐界面章节（各自带线框图与 UE 规则表 `UE1…`）、界面流程、状态机、全局交互规范。

**完整性门（重要）**：源定稿若缺 §5，或 §5 里没有"界面清单"——即没有任何一节能支撑"一个界面一节"的结构——**停下向用户报告**。这是**定稿自身**的缺口，不是在界面稿里凑合的事：先走 `/sr-gdd-review`（确认问题）或 `/sr-gdd-fix`（补界面章节）把定稿补全，再回来出稿。
完成判据：源文件、源定稿头部两字段、界面范围、截图目录四项明确；**源文件已确认是 `doc_type: final_gdd`**（`status: active`，或已标注的 `provisional`），非定稿已停下并给出去路；`provisional` 的 `content.json.footer` 已标记为工作版；完整性门有结论。

### 第 2 步 · 结构抽取（定稿 §5 → content.json）

**默认全量重做：每一版 `content.json` 都从当前定稿 §5 整份重抽，不逐条沿用旧 `content.json`。** 上一版只有两个用途——回查"上次怎么抽的"、以及留档；**它不是这一版的输入**。理由：沿用会让"定稿已经删掉的内容"有存活通道（2026-10-16 实例：宣讲稿侧就有一句版式描述在定稿删掉后仍留在页面上，一路带到第三次重渲才被用户肉眼发现）。

按 `references/content-schema.md` 的字段映射表，把定稿 **§5** 重排成 `content.json`。**只搬运，不发明**；§5 之外的章节一律不读进来；映射不了的差异点列出来问用户，不自行决定。规则块写法与章节编排见同一文件。

**只出 §5 是硬边界**：抽完之后回头核一遍 `content.json`，凡是来自 §1–§4、§6–§11 的内容（功能规则、配置字段、多语言键、范围门、埋点、验收标准、交接清单）**一律删掉**——它们是 `/sr-gdd-html` 与定稿本身的职责。

**章节编排**：

1. **01 界面清单与导航**：§5.0 的界面清单，一条 = 一个界面的进入 / 退出方式；
2. **逐界面节（主体）**：§5.1–§5.N 一节一界面，按玩家流程排序；同一界面的通用规则合并到"默认状态"节，其余状态节**只写差异**，不重复；
3. **界面流程**：§5 的完整操作序列（定稿里是 text 图也要转成规则块）；
4. **状态机**（如适用）：状态流转；
5. **全局交互规范**：跨界面约束（弹窗栈、按钮互斥、返回键、多语言、网络容错、刷新）——定稿里是表格也要转成规则块。

界面流程 / 状态机 / 全局交互规范这三节在定稿里不存在时**不硬凑**，如实少几节。
完成判据：`content.json` 落盘；§5 的每个界面清单项都有对应节；无编号残留、无外链、无自造规则、**无非界面内容**。

### 第 3 步 · 截图准备

- 截图目录默认 `<功能目录>\gdd\界面素材_<主题>_<日期>\`（用户给了目录就用用户的）；
- 命名 `两位序号_界面名[_状态].png`，与 `content.json` 的 `image` 字段一一对应（大小写、空格严格一致）；
- 截图应为**完整界面**（不裁控件局部），Figma 导出按 2x 或原始分辨率；
- 缺图的界面：`image` 填 `null` + 补 `guide`，左栏渲染指路占位框——**不阻塞交付**；
- 定稿里只有 ASCII 线框图时按"无图"处理，并把线框图**按原样**搬进该节的 `guide` 或规则块（不要重画、不要美化，线框图是定稿的正式内容）；
- **全篇无截图要停下来确认**：当整份定稿一张界面图都没有（常见于只有 ASCII 线框图的定稿），左栏会全是占位框、右栏全是规则，形成"左空右满"的失衡版式；第 4 步的 lint 会报 `全篇无截图` 警告，**这是必须处置的信号，不得静默交付**。两条去路由用户选：① 补界面截图后再出（推荐，UE 同事要照着做界面，图差别很大）；② 明确接受"以规则为主"的纯文字版，并在页脚标注"本页无界面截图"。
- 缺图**不是**用网络图凑数的理由：禁止外链、禁止从别处抓图。
完成判据：`content.json` 中每个 `image` 在截图目录内可命中（或已改为 `guide` 占位）；若全篇无截图，已获用户明确选择。

### 第 4 步 · 红线与双向核对

**必须先跑校验、再生成**（生成器只做字段与图片存在性校验，不查内容红线）：

```bash
python <skill>/tools/lint_content.py --content content.json --img-dir <截图目录>              # ① 红线与结构
python ../sr-gdd-html/tools/orphan_check.py --gdd "<定稿.md>" --content content.json --section 5   # ② 反向核对
```

- `lint_content.py`：必需字段、id/num 唯一性与格式、有图或有指路（不留空）、图片存在性、外链检测，以及上文「内容红线」与「图片红线」的词表检查；同时给出文字墙等视觉风险警告。**红线命中 = 失败**，修 `content.json` 后重跑，不得带警告交付。
- `orphan_check.py --content`（**反向核对**；工具在 `../sr-gdd-html/tools/`，两个 skill 成组安装）：核 `content.json` 里**不该被改写**的硬事实——界面 ID（`UI-M1`）、反引号标识、`【】`/`「」`里的 UI 文案、数值＋单位——是否都能在**当前定稿 §5** 找到出处。`--section 5` 顺带把"只出 §5"这条硬边界变成可执行判据。**无出处（内容）每一条都要处置**：① 定稿确实删了它 ⇒ 从 `content.json` 删掉；② 它不该被删 ⇒ 走 `/sr-gdd-fix` 补回定稿再重抽。
- **它的边界要如实说**：`content.json` 的规则正文按控件块**重写归并**（规范明写"UE 编号不进正文"），逐句比对不成立 ⇒ 工具只核硬事实，规则正文计入"无法机械核对"，仍靠第 2 步人工核对（见 `references/content-schema.md` 越线清单末句）。别把"工具全过"当成"内容都对"。
完成判据：`lint_content.py` 退出码 0 且无 warning 残留；`orphan_check.py` 退出码 0（无"无出处·内容"）。

### 第 5 步 · 渲染

```bash
python <skill>/resources/toolkit/生成脚本/gen_01.py --content content.json --img-dir <截图目录> --out "<输出.html>"
```

生成器产出单文件自包含 HTML（截图 base64 内嵌）。生成器报 `[FAIL]` 一律先修源数据，不手改 HTML 输出——**HTML 是派生物**，任何内容修订都回到 `content.json` 重跑。

紧接着**必须**打一次吸顶版式补丁（**同一份 HTML，原地打，幂等**）：

```bash
node <skill>/tools/apply_sticky_layout.mjs "<输出.html>"
```

「左图右文」的双栏与 `position: sticky` 是工具包自带的，但**光有声明不等于吸得住**：竖屏界面截图（1080×1920）按栏宽 380px 显示时高 **675px**，比右栏规则还高——图自己就是最高的元素，sticky 没有可移动空间，滚起来图照样走（实测示例页两个截面的**吸顶行程都是 0px**）。补丁只做一件事：给图加视口高度上限（`46vh`，窄屏自动取消），右栏只要比它高就吸得住。
完成判据：HTML 落盘，渲染器回报的节数与图片数符合预期，且吸顶补丁已应用（`--check` 退出码 0）。

### 第 6 步 · 轻量视觉冒烟（每次必检）

五项每次必过，**并以无头浏览器实际渲染确认**——只读 HTML 源码不算通过：

- [ ] 无破图（每张图解码成功）
- [ ] 无横向溢出 / 重叠
- [ ] 无大段文字墙（规则已块化，工具会点名超阈值的规则正文）
- [ ] **左图真的吸得住**：既看 `position: sticky` 的声明，也量"吸顶可用行程（双栏行高 − 图高）"，并滚进长截面**实测**图还在不在视口里——声明在、行程 0 的时候图照样滚走（工具会点名）
- [ ] 章节导航锚点可用（逐个锚点能跳到对应节）

首选内置检查器（自动判定上面五项 + 整页截图，Node ≥ 22，无第三方依赖，自动拉起本机 Chrome/Edge），并顺带守住"图片必须 data: 内嵌"的承载红线：

```bash
node <skill>/tools/smoke_check.mjs --html "<输出.html>" --out smoke.png
```

**退出码非 0 即不予交付。** Node 不可用时的降级路径：

```bash
# Chrome / Edge 无头截图（路径含中文时先复制到 ASCII 路径）
chrome --headless=new --disable-gpu --window-size=1440,6000 --screenshot=smoke.png "file:///<输出.html 的绝对路径>"
```

**无论哪条路径，最后都要人眼过一遍截图**（工具判"结构没坏"，判不了"UE 同事照着能不能做出界面"）。发现问题改 `content.json` 重跑；修复后重检。无需全页面逐屏验收。
完成判据：五项全过，且截图已目视复核（不是"看起来应该没问题"）。

### 第 7 步 · Human Gate

向用户呈现**界面 UE 规则 HTML 与自查结果**，等待选择：

```
approve / revise / resupply_screenshots / reject
```
完成判据：用户已从上述选项中明确选择其一；**用户没表态之前不许替他写任何决策** —— 但用户每给一次拍板或纠偏，就按 `../sr-askme/references/decision-recording.md` 当场追加一条（门内迭代也各记一条）。

（本 skill 不设 `request_missing_evidence`——缺材料在第 1/3 步已问过。）

- `revise`：按意见改 `content.json` 重跑第 4–6 步；
- `resupply_screenshots`：换/补截图后重跑第 3–6 步；

## 维护提示

`resources/toolkit/` 是**原样内置**的他方工具包，来自 AI_SR 交互交付流程的「宣讲 HTML 生成工具包」（2026-09-10 版），与团队既有交付物 `01_宣讲会交付.html` 同规格。原样内置是为了**离线复现同一套视觉**、不依赖任何人本机路径，代价是仓库多出工具包体积。工具包 README 明确说明"拷贝文件夹当技能装会跟源头漂移"——本目录内的文件请勿就地修改；需要更新时按 `resources/PROVENANCE.md` 记录的 sha256 校验新版本，整体替换并更新校验值。

工具包有两处**面向宣讲场景**的硬编码文案，本 skill 沿用不改（改了就破坏 sha256 校验、也就不再"同源同规格"）：生成器 `<title>` 后缀固定为「交互交付宣讲」、kicker 默认值「交互交付宣讲」。页面上真正给人看的是 `content.json` 的 `kicker`（本 skill 规定写 `SR · 界面 UE 规则`）、`title` 与 `footer`；浏览器标签页那一行后缀不影响交付。

**工具包的版式缺陷在 skill 侧补，不改工具包**：`gen_01.py` 的双栏 + 左图 `position: sticky` 只给了声明，没给图视口高度上限——竖屏界面图必然比右栏高，吸顶是假的（`tools/apply_sticky_layout.mjs` 的注释里记着实测数据）。所以渲染后必须跑那个补丁，判据是第 6 步的第 4 项。工具包升级换了类名时，补丁会匹配不到 `.shot img`、页面退回"图按栏宽显示"的老样子（仍可读），冒烟第 4 项会红、提示你去看。
