## 本 skill 自研件（非工具包原件）

| 文件 | 说明 |
| --- | --- |
| `tools/lint_content.py` | 内容红线 + 越线 + 结构校验器。生成器 `gen_01.py` 只校验字段与图片存在性，不查"确认编号/过程措辞"这类红线，也不查"验收标准 AC… 之类的非界面内容混进来"；本脚本补上这两层，在渲染前必须跑 |
| `tools/apply_sticky_layout.mjs` | **吸顶版式补丁**：给界面图加视口高度上限（`46vh`，窄屏取消）。工具包的双栏与左图 `position: sticky` 只给了**声明**——而竖屏界面图（1080×1920 按栏宽 380px 显示）高 **675px**，比右栏规则还高，图自己就是最高的元素，sticky 没有可移动空间 ⇒ 实测示例页两个截面的**吸顶行程都是 0px**，滚起来图照样走。补上高度上限后右栏只要比图高就吸得住。只加样式、不改内容、幂等；渲染后必须跑 |
| `tools/smoke_check.mjs` | 视觉冒烟检查器。把模板末尾的"轻量视觉冒烟清单"落成可执行判定：破图 / 横向溢出 / 文字墙 / **左图真的吸得住**（吸顶行程 + 滚动实测）/ 锚点命中，外加"图片必须 data: 内嵌"的承载红线，并输出整页截图供人目视复核。Node ≥ 22 + 本机 Chrome/Edge，无第三方依赖 |
| `../sr-gdd-html/tools/orphan_check.py`（**不复制副本，跨 skill 引用**） | **反向核对器**：核 `content.json` 里"不该被改写"的硬事实（界面 ID / 反引号标识 / `【】`·`「」`UI 文案 / 数值＋单位）能否在**当前定稿 §5** 找到出处；`--section 5` 顺带把"只出 §5"这条硬边界变成可执行判据。**规则正文查不了**——它按控件块重写归并（规范明写"UE 编号不进正文"），工具把它计入"无法机械核对"，仍靠第 2 步人工核对。与 `/sr-gdd-html` 共用一个实现：那边用 `--draft` 模式核宣讲草稿 |
| `examples/合成示例/` | 合成形态基准（content.json + 占位截图 + 生成产物），替代未入库的真实样例；内容按"从定稿 §5 抽出来"的形态写（界面清单 / 逐界面 / 界面流程 / 全局交互规范） |

## 再同步（上游更新时）

1. 取到新版归档，先校验归档 SHA256 与本文件记录是否一致——一致则无需动作；
2. 不一致时解压，逐个比对上表四个文件的 SHA256，**有变化的整体替换**（不要局部改写）；
3. 替换后更新本文件的版本、归档 SHA256 与逐文件 SHA256；
4. 跑一次 `examples/合成示例/` 的复现命令，确认生成器仍与本 skill 的 `content.json` 结构兼容（生成器若改了 JSON 结构，`SKILL.md` 第 2 步的映射表与 `tools/lint_content.py` 需同步改）；
5. 工具包 README 明确写着"拷贝文件夹当技能装会跟源头漂移"——本条同步流程就是应对漂移的手段，不要省。

```bash
  --content examples/合成示例/content.json \

node tools/apply_sticky_layout.mjs "examples/合成示例/01_界面UE规则_示例.html"   # 吸顶版式补丁
```
