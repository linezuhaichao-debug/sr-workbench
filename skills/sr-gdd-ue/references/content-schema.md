# content.json 结构规范（sr-gdd-ue 第 2 步抽取用）

把定稿 **§5 用户体验与界面流程**重排成 `content.json` 时**只搬运，不发明**；映射不了的差异点列出来问用户，不自行决定。

**每一版都从当前定稿 §5 整份重抽**（不逐条沿用旧 `content.json`）：沿用会让"定稿已经删掉的内容"有存活通道，而"§5 有的稿子里有没有"与"稿子里有的 §5 有没有"是两件事——后者靠第 4 步的反向核对（`orphan_check.py --content --section 5`）兜。

**来源范围是硬边界**：只读 §5。§1–§4、§6–§7 一个字都不抽——见文末「越线清单」。

| content.json 字段 | 来源 | 抽取要求 |
| --- | --- | --- |
| `kicker` | 固定 `SR · 界面 UE 规则` | 用户另行指定时以用户为准 |
| `title` | 定稿功能名 | 不带"GDD / 定稿 / 草案 / v0.x"等文档后缀 |
| `sub` | 封面定位一句话 + 术语口径 | 一句话只允许引 §1「功能概述」的那一句（封面需要它，UE 同事才知道这界面是干嘛的），**不展开 §1 的其余内容**；**同一系统多个叫法必须在此写死**（如"招募=酒馆抽卡 / 召唤=活动内开箱"），避免做界面对不上 |
| `steps` | §5.0 界面清单的界面顺序 | 按玩家流程排成 4–10 个胶囊（写界面名即可，进入/退出方式放下面的 01 节）；不写单行长句 |
| `footer` | 包名 · 版本 · 源定稿文件名 · 日期 | 保留源文件名，便于 UE 同事回溯；`provisional` 工作版必须写"工作版，非正式定稿" |
| `sections[].id` | 自拟 | 唯一，`^[A-Za-z][A-Za-z0-9_-]*$`（锚点用） |
| `sections[].num` | 自拟 | 两位序号 `01`…，**按玩家流程排序**，与 id 一致递增 |
| `sections[].title` | 界面章节标题 | 格式 `界面名 · 状态` |
| `sections[].image` | 截图目录内文件名 | 与截图文件同名；无图填 `null` |
| `sections[].image_note` | 原型 Frame 名 / 来源说明 | 图注第二行；省略时默认取文件名去后缀 |
| `sections[].guide` | 指路文案 | **无图时必须给**（指向复用组件 / 其它系统界面，或**原样搬来的 ASCII 线框图**），不留空 |
| `sections[].rules` | 该界面的 UE 规则表 | `[["块标题","规则正文"], …]`，一条 = 一个规则块 |

## 规则块写法（右栏质量的关键）

- 块标题 = 该条规则的**主语**（控件名 / 区域名 / 行为名，如"底部按钮组"、"奖励格子"、"异常"），**不带编号**；
- 定稿 §5 的 UE 规则表是 `| 编号 | 规则（详细） |` 的逐条表：**按主语归并**——同一控件的多条 UE 规则合并进同一个块，一个块只讲一个控件；主语不同的不硬并；
- GDD 里的 **UE 编号不进正文**——UE 同事按控件名找位置；确需交叉引用时引用到节级（如"见全局交互规范"），不引入新编号层级；
- 正文按 **展示 / 点击 / 反馈 / 异常** 组织，一句话说清一件事；
- **禁止 `<br>` 连排成文字墙**：超过 ~4 行就拆块；整条规则超 240 字会被 `tools/lint_content.py` 点名；
- 文本内允许 `<b>`/`<br>`（仅作强调与分行），禁止内联样式与外部资源。

## 章节编排（顺序即页面顺序）

1. **01 界面清单与导航**（来源 §5.0）：一条 = 一个界面，正文写它的**进入方式 / 退出方式**。这一节是 UE 同事的总览，不重复下面逐界面节的行为细节。
2. **逐界面节（主体，来源 §5.1–§5.N）**：一节一界面，按玩家流程排序。同一界面的通用规则合并到"默认状态"节，其余状态节**只写差异**，不重复。
3. **界面流程**（来源 §5 的界面流程 text 图）：把序列转成规则块（一块 = 一段流程），不贴 ASCII 图。
4. **状态机**（来源 §5 的状态机，如适用）：状态流转转成规则块；定稿没有这节就不出。
5. **全局交互规范**（来源 §5 的全局交互规范表）：一块 = 一类规范（弹窗栈 / 按钮互斥 / 返回键 / 多语言 / 网络容错 / 刷新）。

第 3–5 节在定稿里不存在时**不硬凑**，如实少几节。

## 规则块正文的组织口径

| 场景 | 怎么写 |
| --- | --- |
| 控件三态（已领 / 可领 / 未达成） | 一块写完三态，每态一句"展示什么样 + 能不能点" |
| 弹窗 | 蒙层（拦截穿透 / 点击空白关闭）、标题、内容、按钮、关闭后的落点，各成一块 |
| 无独立界面的流程（走既有系统） | `image: null` + `guide` 写指路，`rules` 只写**触发关系与结果**，不展开那个系统的内部设计 |
| 数值 | 照抄定稿口径（`参考值 X，待定` / `配表名.字段名`），不新增、不换算、不补全 |

## 越线清单（出现即返工）

抽完后回头核一遍 `content.json`，下面这些**一句都不许有**：

- **定稿 §1–§4**：功能概述、本功能不解决什么、核心循环、功能规则 Rn（`sub` 里那一句封面定位除外）；
- **定稿 §6–§7**：配置契约（表清单 / 字段表 / 索引 / 状态）、多语言文本键清单；
- **旧形态定稿的 §8–§11**（2026-10-30 起定稿已不含这四章）：范围门（纳入 / 排除）、数据埋点信号表、验收标准 AC、交接清单——源定稿若还带着它们，同样一句不进；
- **行内混入的 §4 / §6 口径**：规则块正文里**不带** `表名.字段名`、反引号字段名、"不新增 / 不参与折算 / 按既有…规则计算 / 参考值 X，待定 / 待配表"这类口径句 —— 它们来自定稿 §5 的 UE 行，而那一行在定稿里是必需的；UE 稿只留"这个界面长什么样、控件什么行为"。判据见 `tools/lint_content.py` 的两条 FAIL 红线（2026-10-13 补）。**例外**：看着像技术、其实决定界面反应的照留（失败不本地强制成功、跳过动画不改结算结果、结果卡归类、属性侧别、状态以服务端返回为准）；
- **过程性信息**：确认编号 Q1/Q2、用户原话、"拍板 / 已确认 / 跟推荐"、证据编号 E001/T01/C1、Human Gate 选项词；
- **承载红线**：外链图片、`./assets/` 散装目录、内联 `<script>` / 样式 / 事件处理器。

`tools/lint_content.py` 把上面大部分词表化成可执行判据，渲染前必跑；它查不出的（比如"这条规则其实来自 §4 而不是 §5"）由第 2 步人工核对。

**反向核对只认硬事实**（第 4 步）：`../sr-gdd-html/tools/orphan_check.py --content --section 5` 核的是界面 ID、反引号标识、`【】`/`「」`里的 UI 文案、数值＋单位——这些是照抄的，定稿删了哪条规则就会露出来。规则正文因为**按控件块重写归并**（"UE 编号不进正文"），工具把它计入"无法机械核对"：**"工具全过"不等于"内容都对"**，人工那一关不能省。

## 边界纪律

属于其它系统或通用组件的界面（如获取引导弹窗、别的系统详情页），**不展开其内部设计**，只写触发关系，并在该节 `guide` 里声明"不属于本功能"。
