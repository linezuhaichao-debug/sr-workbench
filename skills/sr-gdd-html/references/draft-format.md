# 定稿 → 草稿的映射规范（sr-gdd-html 第 3 步用）

本文件规定：**把一份功能 GDD 定稿（§1–§7）整份重排成一页 am 草稿**时，每一节落到哪里、用什么组件、怎么写。

**总原则：只重排，不改写。** 定稿的每一条规则、每一个数值、每一张表都要在页面上有落点；页面可以换形态（表格转 flow、长段落转列表），但不能增删语义。

---

## 一、草稿骨架

```markdown
---
template: doc
theme: auto
title: <功能名>
subtitle: <功能概述那一句> · 宣讲稿
source: <源定稿文件名>（doc_type: final_gdd · status: active）
---

<Lead：两句话说清这份定稿是什么、这次要解决什么>

## §1 功能概述
…

## §2 本功能不解决什么
…
```

| 键 | 取值 | 说明 |
| --- | --- | --- |
| `template` | **固定 `doc`** | 定稿是长文档、要按顺序读；`doc` 是单列 + 左侧目录，3 个面板以上自动出目录。**不要用 `sheet`**（那是"一屏概览"用的） |
| `theme` | `auto`（默认） | `auto` 在有图/图时用 blueprint、纯文字用 paper；用户当轮指定主题时以用户为准 |
| `title` | 定稿功能名 | 不带"GDD / 定稿 / 草案 / v0.x"后缀 |
| `subtitle` | 定稿 §1 功能概述那一句 + "宣讲稿" | 让人一眼知道这是开会 / 评审用的那一份 |
| `source` | 源文件名 + 头部两字段 + 版本特征（行数 / 字节 / 修改时点） | 显示在页头 meta 行；带上版本特征才叫**源锚**——读者据此核对"这份对应哪一版定稿"（`631 行 / 58,718 字节 / 11:49 版`）。`provisional` 工作版**必须**在这里写明"工作版，非正式定稿" |
| `style` | `80`（默认） | STE 文风检查：只警告。用户要求严格时写 `strict`（不通过就不出页面） |

**面板标题保留定稿的章节号，别自己编号**（`## §4.1 R1 升级条件`）——读者拿页面对着定稿回查时，编号是唯一可靠的锚。am 原版会给每个面板**自动分配一个字母**（A/B/C…）；**本 skill 内置的 am 已经不产出它**（面板头部与左侧目录都不带字母），因为定稿标题**已经自带 § 编号**，两套编号叠着纯噪音。两条要知道的：

- 草稿里**不要**自己写字母（`## A §4.1 …`）——那样 § 编号会变成标题的第二个词，目录里看着像标题的一部分；
- `am patch --panel` **仍可用字母引用**（`--panel "G"` 或 `--panel "§4.1 R1 升级条件"`）——字母是 am 内部的面板序号，与页面上显不显示无关。

## 二、逐节映射（§1–§7 一份都不许少）

| 定稿章节 | 面板 | 用什么写 |
| --- | --- | --- |
| §1 功能概述 | `## §1 功能概述` | 定稿 §1 就是一段话：照抄成段落，不拆列表、不加小标题 |
| §2 本功能不解决什么 | `## §2 本功能不解决什么` | 表格（不解决项 / 原因）；不解决项列写 `no` 徽章 |
| §3 核心循环（即时 / 单次会话 / 长期） | `## §3 核心循环` | 三段各一个 ```flow LR 代码块（`动作 -> 反馈 -> 奖励`）；原文是 text 图就按箭头拆行 |
| §4 功能规则 R1…Rn | `## §4.1 R1 <规则组名>`、`## §4.2 …` | **一个规则组一个面板**，组内用表格（规则 / 细节 / 配置字段）；组数多时每面板只放一组。**不写口径说明块** —— 组号沿用 / 「配置字段」列口径是撰写侧规范，不上页；源定稿 §4 章首没有内容时，`## §4 功能规则` 只作节标题（保目录落点），正文留空 |
| §5.0 界面清单总览 | `## §5.0 界面清单` | 表格（界面ID / 名称 / 进入方式 / 退出方式） |
| §5.1–§5.N 逐界面 | `## §5.N <界面ID> <界面名>`，一界面一面板 | 有截图 → `![界面名 · 状态](/绝对路径/xx.png)` 单独一行；只有 ASCII 线框图 → 原样贴进 ` ```text ` 代码块；UE 规则表 → 表格（编号 / 规则） |
| §5 界面流程 | `## §5 界面流程` | ```flow LR（节点 = 界面/状态，边 = 触发动作）；线性长链可拆成两三个 flow |
| §5 状态机（如适用） | `## §5 状态机` | ```flow LR 或 ```sequence；状态用 `(状态)` 圆角节点，迁移条件写在边标签 |
| §5 全局交互规范 | `## §5 全局交互规范` | 表格（规范 / 规则） |
| §6 配置契约（每工作簿一节 `### 6.N`） | `## §6.N <工作簿名>`，**一个工作簿一个面板** | 表清单 → 表格（中文表名 / 输出名 / 索引 / 状态，状态列写 `ok 已有` / `warn 新增` / `warn 新增命名待定`）；每张表的字段表 → 紧跟一个表格（中文字段 / 英文字段 / 结构 / 含义）；key-value 表 → 键表。**`状态` 只出现在表清单那一行**，字段表不带状态列（定稿就是这么定的，别改） |
| §7 多语言文本 | `## §7 多语言文本` | 表格**八列照抄**（键 / 中文文案 / 占位符 / 状态 / UI位置 / UI状态 / 触发 / 用途；源定稿带 `候选Key名` 时**九列照抄**），**列不许合并、不许删**；`状态` 列用徽章，按注册词表取色（`ok 已核验Key` / `ok 建议复用` / `warn 新增需求` / `warn 修改需求` / `warn 已提供Key-未核验` / `warn 待分配Key` / `warn 待确认` / `no 本功能不再引用` / `no 不纳入AI读版`）；`UI状态` 是工程枚举，照写英文、不翻译也不套徽章；`占位符` 里的 `$0` / `$1` 原样保留；表下的**表级核验注**照抄成一条 callout |

**界面节的版式是自动的（别手写）**：一个面板里 `![图]` 后面**还有别的块**（规则表 / 段落），渲染出来就是 **图左、规则右、图吸顶**（内置 am 自带的样式）—— 规则再长，图也留在视野里。所以草稿里**照常写**（图单独一行、规则表紧跟其后），**不要**为了双栏去写 `html` 代码块、也不要调顺序。图的列宽 300–450px、显示高度上限 69vh（竖屏界面截图比早先大一倍半；只放宽列宽没用，限高才是真正卡住尺寸的那个），窄屏（≤900px）自动退回单栏；一个面板里只有一张图、后面没别的东西时不会被套两栏。**图上的小字不必靠"把版式撑大"解决**——正文大图点一下就全屏看原图（可翻页、可切 1:1 原始像素），这是内置 am 的行为，草稿里**不用**、也**不要**自己写任何放大按钮。

★ **图与规则表之间不要夹段落**——内置 am 的双栏靠 `.am-figure + table` 相邻选择器：中间插一行文字，双栏就不生效（图变成上下堆叠，页面白长一截）。要补说明就写在规则表**之后**（2026-10-16 实测：§5.2 因一句版式描述从双栏 644px 退回堆叠 1249px）。

**定稿缺哪一节就少哪个面板**——不硬凑、不补写、不臆造。但**定稿有的必须都有**（判据见第四节）。**定稿只有 §1–§7**（2026-10-30 起）——范围门、数据埋点信号、验收标准、交接清单不在定稿里，**也不上宣讲页**；源定稿还带着这四章（旧形态）时，照实重排，但不要从别处补。

## 三、组件选择与写法

详细语法**现查现用**，不要凭记忆写：

```bash
node <skill>/resources/am/am.mjs list            # 模板 / 主题 / 组件清单
node <skill>/resources/am/am.mjs help <组件>     # 某个组件的语法与示例
node <skill>/resources/am/am.mjs help format     # 草稿格式总览
```

| 信息的形状 | 用什么 | 最小写法 |
| --- | --- | --- |
| 结论 / 提示 / 警告 | `callout` | ` ```callout ok 标题 ` + Markdown 正文；类型取 `info` / `ok` / `warn` / `err` |
| 元信息 / 抬头块 | `kv` | `键: 值`，`* 键: 值` 跨整行 |
| 流程 / 循环 / 状态机 | `flow [LR]` | `A -> B: 标签`、`A --> C`（虚线）、`(开始)`、`{判断?}`、`*强调`、`group 组名: A, B` |
| 界面之间的消息时序 | `sequence` | `A -> B: 请求`、`B --> A: 返回`、`== 阶段 ==` |
| 层级 / 归属 | `tree [list]` | 缩进定层级，`标签 \| 说明` |
| 阶段 / 版本演进 | `timeline [h\|v]` | `时间 \| 标题 \| 说明`，`*` 高亮 |
| 数值 vs 上限 | `limits` | `标签 \| 13 / 20 \| 单位`、`标签 \| max 20` |
| **任何表格** | Markdown 表格 | 状态列写 `ok` / `no` / `warn` → ✓ / ✗ / ! 徽章（后面可以跟字，如 `ok 已有`） |
| 真实界面截图 | 图片 | `![界面名 · 状态](/绝对/路径.png)` **单独一行**；≤5 MB；am 会把它**内嵌进页面**。★ **定稿里的图是相对路径**（`assets/images/xx.png`，落在 `gdd\assets\images\`）——草稿里**不照抄相对路径**，要换成该文件的**绝对路径**（`D:/…/features/<主题>/gdd/assets/images/xx.png`）。★ **路径一律用正斜杠 `/`** —— Windows 的反斜杠会被 Markdown 当转义吃掉：`D:\TimeMachine\.tmp\x.png` 里的 `\t`、`\f` 会变成控制字符，渲染器报 `Image not found: "D:\TimeMachine.tmp\x.png"`（实测踩过）。要么写 `D:/TimeMachine/.tmp/x.png`，要么把整条路径包进尖括号 `<D:\...>` |
| ASCII 线框图 / 目录树 / text 图 | ```text 代码块 | 原样贴，等宽显示；**不要**改画成别的样子 |
| 决策点（要读者拍板） | `ask` | 仅在用户明确要在页面上收决策时用 |

**优先级：能用表格就别用图，能用内置组件就别写 HTML。** ```html / ```svg 代码块是逃生口，只在没有任何组件能表达时才用；用了要在交付说明里讲清为什么。

## 四、不漏信息 + 不残留（**双向核对**，这一步是本 skill 的存在理由）

第 2 步先跑一次盘点，把定稿的**信息锚点**列出来当基线：

```bash
python <skill>/tools/cover_check.py --gdd "<定稿.md>" --list
```

第 3 步写完草稿后，**两个方向各跑一次**：

```bash
python <skill>/tools/cover_check.py  --gdd "<定稿.md>" --draft "<草稿.md>"   # 正向：定稿 → 草稿（不许漏）
python <skill>/tools/orphan_check.py --gdd "<定稿.md>" --draft "<草稿.md>"   # 反向：草稿 → 定稿（不许残留）
```

**正向 `cover_check`** 抽四类锚点：**章节标题**、**表格每一行的首列**（规则名 / 界面名 / 字段名 / 键名 / AC 编号…）、**反引号里的标识**（`表名.字段名`、文件名、状态枚举）、**Rn / UEn / ACn 编号**。未命中的锚点逐条列出，**每一条都要处置**，二选一：

1. 确实是漏了 → 补进草稿，重跑；
2. 确实不需要单独出现（被合并进一句话、或作为表头出现）→ 在呈给用户的报告里**写明理由**，不许沉默略过。

**反向 `orphan_check`** 按**块**（散句 / 整段代码块 / 表格整行 / 标题）与定稿取最长公共子串，回答"草稿里有没有定稿已经删掉的东西"。两档结论：

- **无出处（内容）**——**不通过**，每一条都要处置：① 定稿确实删了它 → 从草稿删掉（含为版面自造的导航句、摘要句）；② 它不该被删 → 走 `/sr-gdd-fix` 补回定稿再重渲，**不许让草稿自己留着**；
- **无出处（结构）**与**疑改写**——只提示：标题层属编排；"疑改写"多半是重画图与换标点造成的低重合。逐条看一眼即可。

**为什么必须有反向那一半**（2026-10-16 实例）：`cover_check` 当时报 **355/355 全命中**，而定稿 11:33 删掉的一句版式描述还在页面上——正向判据**只回答"定稿有的草稿有没有"，不回答"草稿有没有定稿已经删掉的"**。一句话：**两个方向合起来，才是"草稿是当前定稿的完全派生物"**；只跑正向等于放行残留（见第五节红线）。

## 五、红线（越线即返工）

- **不改数值口径**：定稿写 `表名.字段名` 的照写，写"待配表"的照写，写"参考值 X，待定"的照写。不新增、不换算、不补全、不四舍五入。
- **不补设计结论**：定稿没写的规则、界面、状态、边界，一个字都不加。页面是定稿的**另一种呈现**，不是新版本。
- **不残留**：草稿是**当前定稿**的完全派生物——定稿删掉的内容不许留在页面上；为版面自造的导航句与摘要句同样算残留。页面级元信息只写在**导语**里（首个标题之前，也是 `orphan_check.py` 唯一跳过的地方）。判据是 `tools/orphan_check.py`（见第四节）。
- **不删章节**：§1–§7 有哪节出哪节；节内条目也不许因为"太细"而略过
  （覆盖核对会点名——见第四节）。
- **不放过程留痕**：证据编号、假设台账、拍板记录属于成稿附录 A，定稿里本来就没有，更不该出现在页面上。
- **不产生外链**：图片一律用**本机绝对路径**交给 am 内嵌；正文里不写 `http(s)://` 链接（离线打开会失效，也在外发时暴露内网地址）。
- **不生成图**：只用已有的界面截图。没有图就让该节纯文字，**不要**画示意图充当界面图。
- **不改 `template: doc` 与章节号**：目录与回查都靠它。

## 六、写作纪律（中文 STE，`am render` 会自动检查）

页面正文**不是定稿原文的复制**——定稿是给程序看的，句式密、术语多；页面要把它拆成能读的句子。改动只允许发生在**表达层**：

- **一句说一件事**；步骤（有序列表）≤ 35 字，描述句 ≤ 45 字，一段 ≤ 6 句；
- 主动语态，动宾直说：写「点击升级按钮」，不写「升级按钮应当被点击」；
- **同一个东西始终用同一个名字**（定稿的术语与配置命名口径不变）；
- 不用轻动词：`进行优化` → `优化`，`加以说明` → `说明`；不连用三个 `的`；
- 不用模糊量词：`尽快`、`若干`、`大概`、`多次` 一律换成确定说法或照抄定稿的原文；
- 数字后的 `以上 / 以下 / 以内` 写成 `大于 / 不小于 / 不超过`；
- 同一含义只用一个词：`单击` → `点击`，`键入` → `输入`，`入参` → `参数`；
- 表格单元格里写短句，不写段落；长规则拆成多行或改用列表。

`am render` 报 `STE n warnings` 时按提示改写后重跑，最多两轮；两轮后仍有警告，保留页面并在交付说明里如实讲。

## 七、面板切分与页长

- **一个面板回答一个问题**：§4 按规则组切，§5 按界面切，§6 按工作簿切；
- 单个面板里表格超过约 20 行、或正文超过两屏 → 拆面板；
- 面板总数通常 9–24 个（定稿 §1–§7 全出）；超过 30 个时优先合并同类小节，**但不许靠删内容来缩短**；
- 页面是给人读的，不是给人"扫一眼"的——宁可长，不可漏。
