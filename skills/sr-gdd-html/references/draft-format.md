# 定稿 → 草稿的映射规范（sr-gdd-html 第 3 步用）

本文件规定：**把一份功能 GDD 定稿（§1–§11）整份重排成一页 am 草稿**时，每一节落到哪里、用什么组件、怎么写。

**总原则：只重排，不改写。** 定稿的每一条规则、每一个数值、每一张表都要在页面上有落点；页面可以换形态（表格转 flow、长段落转列表），但不能增删语义。

---

## 一、草稿骨架

```markdown
---
template: doc
theme: auto
title: <功能名>
subtitle: <一句话功能> · 定稿人读版
source: <源定稿文件名>（doc_type: final_gdd · status: active）
---

<Lead：两句话说清这份定稿是什么、这次要解决什么>

## §1 功能意图
…

## §2 玩家动词
…
```

| 键 | 取值 | 说明 |
| --- | --- | --- |
| `template` | **固定 `doc`** | 定稿是长文档、要按顺序读；`doc` 是单列 + 左侧目录，3 个面板以上自动出目录。**不要用 `sheet`**（那是"一屏概览"用的） |
| `theme` | `auto`（默认） | `auto` 在有图/图时用 blueprint、纯文字用 paper；用户当轮指定主题时以用户为准 |
| `title` | 定稿功能名 | 不带"GDD / 定稿 / 草案 / v0.x"后缀 |
| `subtitle` | 一句话功能 + "定稿人读版" | 让人一眼知道这是给人读的那一版 |
| `source` | 源文件名 + 头部两字段 | 显示在页头 meta 行，便于回查；`provisional` 工作版**必须**在这里写明"工作版，非正式定稿" |
| `style` | `80`（默认） | STE 文风检查：只警告。用户要求严格时写 `strict`（不通过就不出页面） |

**面板标题保留定稿的章节号，别自己编号**（`## §4.1 R1 升级条件`）——读者拿页面对着定稿回查时，编号是唯一可靠的锚。am 原版会给每个面板**自动分配一个字母**（A/B/C…）；**本 skill 内置的 am 已经不产出它**（面板头部与左侧目录都不带字母），因为定稿标题**已经自带 § 编号**，两套编号叠着纯噪音。两条要知道的：

- 草稿里**不要**自己写字母（`## A §4.1 …`）——那样 § 编号会变成标题的第二个词，目录里看着像标题的一部分；
- `am patch --panel` **仍可用字母引用**（`--panel "G"` 或 `--panel "§4.1 R1 升级条件"`）——字母是 am 内部的面板序号，与页面上显不显示无关。

## 二、逐节映射（§1–§11 一份都不许少）

| 定稿章节 | 面板 | 用什么写 |
| --- | --- | --- |
| §1 功能意图 | `## §1 功能意图` | 一句话功能 → 段落；为什么要做 → 段落或列表；本功能不解决什么 → 表格（不解决项列写 `no` 徽章） |
| §2 玩家动词清单 | `## §2 玩家动词` | 表格（动词类型 / 玩家动作） |
| §3 核心循环（即时 / 单次会话 / 长期） | `## §3 核心循环` | 三段各一个 ```flow LR 代码块（`动作 -> 反馈 -> 奖励`）；原文是 text 图就按箭头拆行 |
| §4 功能规则 R1…Rn | `## §4.1 R1 <规则组名>`、`## §4.2 …` | **一个规则组一个面板**，组内用表格（规则 / 细节 / 配置字段）；组数多时每面板只放一组 |
| §5.0 界面清单总览 | `## §5.0 界面清单` | 表格（界面ID / 名称 / 进入方式 / 退出方式） |
| §5.1–§5.N 逐界面 | `## §5.N <界面ID> <界面名>`，一界面一面板 | 有截图 → `![界面名 · 状态](/绝对路径/xx.png)` 单独一行；只有 ASCII 线框图 → 原样贴进 ` ```text ` 代码块；UE 规则表 → 表格（编号 / 规则） |
| §5 界面流程 | `## §5 界面流程` | ```flow LR（节点 = 界面/状态，边 = 触发动作）；线性长链可拆成两三个 flow |
| §5 状态机（如适用） | `## §5 状态机` | ```flow LR 或 ```sequence；状态用 `(状态)` 圆角节点，迁移条件写在边标签 |
| §5 全局交互规范 | `## §5 全局交互规范` | 表格（规范 / 规则） |
| §6 配置契约（每工作簿一节 `### 6.N`） | `## §6.N <工作簿名>`，**一个工作簿一个面板** | 表清单 → 表格（中文表名 / 输出名 / 索引 / 状态，状态列写 `ok 已有` / `warn 新增` / `warn 新增命名待定`）；每张表的字段表 → 紧跟一个表格（中文字段 / 英文字段 / 结构 / 含义）；key-value 表 → 键表。**`状态` 只出现在表清单那一行**，字段表不带状态列（定稿就是这么定的，别改） |
| §7 多语言文本 | `## §7 多语言文本` | 表格（键 / 中文文案 / 状态）；状态列用徽章（`ok 已有` / `warn 新增` / `warn 待配表`） |
| §8 范围门 | `## §8 范围门` | 表格（范围层级 / 纳入 / 排除），纳入列可写 `ok`、排除列写 `no` 让边界一眼可见 |
| §9 数据埋点信号 | `## §9 数据埋点信号` | 表格（信号 / 用途） |
| §10 验收标准 | `## §10 验收标准` | 表格（编号 / 标准 / 优先级）；优先级用文本 `P0` / `P1`，**不要**套 ok/warn 徽章（那会让 P0/P1 看起来像通过/警告） |
| §11 交接清单 | `## §11 交接清单` | 表格（角色 / 需要内容 / 负责人）；"负责人待定"照写 |

**界面节的版式是自动的（别手写）**：一个面板里 `![图]` 后面**还有别的块**（规则表 / 段落），渲染出来就是 **图左、规则右、图吸顶**（内置 am 自带的样式）—— 规则再长，图也留在视野里。所以草稿里**照常写**（图单独一行、规则表紧跟其后），**不要**为了双栏去写 `html` 代码块、也不要调顺序。图的显示高度被限制在 46vh（一屏内看得完），窄屏（≤900px）自动退回单栏；一个面板里只有一张图、后面没别的东西时不会被套两栏。

**定稿缺哪一节就少哪个面板**——不硬凑、不补写、不臆造。但**定稿有的必须都有**（判据见第四节）。

## 三、组件选择与写法

详细语法**现查现用**，不要凭记忆写：

```bash
node <skill>/resources/am/am.mjs list            # 模板 / 主题 / 组件清单
node <skill>/resources/am/am.mjs help <组件>     # 某个组件的语法与示例
node <skill>/resources/am/am.mjs help format     # 草稿格式总览
```

| 信息的形状 | 用什么 | 最小写法 |
| --- | --- | --- |
| 结论 / 提示 / 警告 | `callout` | ` ```callout ok 标题 ` + Markdown 正文；类型取 `info` / `ok` / `warn` / `err` |
| 元信息 / 抬头块 | `kv` | `键: 值`，`* 键: 值` 跨整行 |
| 流程 / 循环 / 状态机 | `flow [LR]` | `A -> B: 标签`、`A --> C`（虚线）、`(开始)`、`{判断?}`、`*强调`、`group 组名: A, B` |
| 界面之间的消息时序 | `sequence` | `A -> B: 请求`、`B --> A: 返回`、`== 阶段 ==` |
| 层级 / 归属 | `tree [list]` | 缩进定层级，`标签 \| 说明` |
| 阶段 / 版本演进 | `timeline [h\|v]` | `时间 \| 标题 \| 说明`，`*` 高亮 |
| 数值 vs 上限 | `limits` | `标签 \| 13 / 20 \| 单位`、`标签 \| max 20` |
| **任何表格** | Markdown 表格 | 状态列写 `ok` / `no` / `warn` → ✓ / ✗ / ! 徽章（后面可以跟字，如 `ok 已有`） |
| 真实界面截图 | 图片 | `![界面名 · 状态](/绝对/路径.png)` **单独一行**；≤5 MB；am 会把它**内嵌进页面** |
| ASCII 线框图 / 目录树 / text 图 | ```text 代码块 | 原样贴，等宽显示；**不要**改画成别的样子 |
| 决策点（要读者拍板） | `ask` | 仅在用户明确要在页面上收决策时用 |

**优先级：能用表格就别用图，能用内置组件就别写 HTML。** ```html / ```svg 代码块是逃生口，只在没有任何组件能表达时才用；用了要在交付说明里讲清为什么。

## 四、不漏信息（这一步是本 skill 的存在理由）

第 2 步先跑一次盘点，把定稿的**信息锚点**列出来当基线：

```bash
python <skill>/tools/cover_check.py --gdd "<定稿.md>" --list
```

第 3 步写完草稿后，再用同一份基线核对草稿：

```bash
python <skill>/tools/cover_check.py --gdd "<定稿.md>" --draft "<草稿.md>"
```

它抽的锚点是：**章节标题**、**表格每一行的首列**（规则名 / 界面名 / 字段名 / 键名 / AC 编号…）、**反引号里的标识**（`表名.字段名`、文件名、状态枚举）、**Rn / UEn / ACn 编号**。

未命中的锚点会逐条列出来，**每一条都要处置**，二选一：

1. 确实是漏了 → 补进草稿，重跑；
2. 确实不需要单独出现（被合并进一句话、或作为表头出现）→ 在呈给用户的报告里**写明理由**，不许沉默略过。

它查不出"语义被改写"——所以还有一条人判据：**页面上任何一句话，都要能在定稿里找到出处**；定稿没写的不许补（见第五节红线）。

## 五、红线（越线即返工）

- **不改数值口径**：定稿写 `表名.字段名` 的照写，写"待配表"的照写，写"参考值 X，待定"的照写。不新增、不换算、不补全、不四舍五入。
- **不补设计结论**：定稿没写的规则、界面、状态、边界，一个字都不加。页面是定稿的**另一种呈现**，不是新版本。
- **不删章节**：§1–§11 有哪节出哪节；节内条目也不许因为"太细"而略过
  （覆盖核对会点名——见第四节）。
- **不放过程留痕**：证据编号、假设台账、拍板记录属于成稿附录 A，定稿里本来就没有，更不该出现在页面上。
- **不产生外链**：图片一律用**本机绝对路径**交给 am 内嵌；正文里不写 `http(s)://` 链接（离线打开会失效，也在外发时暴露内网地址）。
- **不生成图**：只用已有的界面截图。没有图就让该节纯文字，**不要**画示意图充当界面图。
- **不改 `template: doc` 与章节号**：目录与回查都靠它。

## 六、写作纪律（中文 STE，`am render` 会自动检查）

页面正文**不是定稿原文的复制**——定稿是给程序看的，句式密、术语多；页面要把它拆成能读的句子。改动只允许发生在**表达层**：

- **一句说一件事**；步骤（有序列表）≤ 35 字，描述句 ≤ 45 字，一段 ≤ 6 句；
- 主动语态，动宾直说：写「点击升级按钮」，不写「升级按钮应当被点击」；
- **同一个东西始终用同一个名字**（定稿的术语与配置命名口径不变）；
- 不用轻动词：`进行优化` → `优化`，`加以说明` → `说明`；不连用三个 `的`；
- 不用模糊量词：`尽快`、`若干`、`大概`、`多次` 一律换成确定说法或照抄定稿的原文；
- 数字后的 `以上 / 以下 / 以内` 写成 `大于 / 不小于 / 不超过`；
- 同一含义只用一个词：`单击` → `点击`，`键入` → `输入`，`入参` → `参数`；
- 表格单元格里写短句，不写段落；长规则拆成多行或改用列表。

`am render` 报 `STE n warnings` 时按提示改写后重跑，最多两轮；两轮后仍有警告，保留页面并在交付说明里如实讲。

## 七、面板切分与页长

- **一个面板回答一个问题**：§4 按规则组切，§5 按界面切，§6 按工作簿切；
- 单个面板里表格超过约 20 行、或正文超过两屏 → 拆面板；
- 面板总数通常 12–30 个（定稿 §1–§11 全出）；超过 35 个时优先合并同类小节，**但不许靠删内容来缩短**；
- 页面是给人读的，不是给人"扫一眼"的——宁可长，不可漏。
