# 宣讲稿 HTML 工作流（SR-GDD-HTML）

## 功能说明

**唯一输出：宣讲稿 HTML（单文件自包含，交付名 `<主题>_宣讲.html`）**。把一份功能 GDD **定稿**（`<功能目录>\gdd\<主题>_定稿.md`）**整份**重排成一份**开会 / 评审能直接投屏或发出去**的宣讲稿：§1–§11 一节不少，但换成人读得下去的样子——分节成页、长表格留住、流程与状态画成图、左侧目录可跳转、明暗主题可切、页内可搜索、截图 base64 内嵌、零外链，可直接发给任何人、离线打开。

**这个 skill 解决的是"定稿是给程序看的、宣讲要给人看"这件事**：定稿的详细度铁律（宁可详尽标注待确认）让它句式密、表格多、术语多，人读起来累。本 skill 不改内容，只换一个读法。

**界面节保留"对着图读规则"的读法**：§5 那种"界面图 + UE 规则表"的面板，渲染出来就是 **图左、规则右、图吸顶**——规则再长，图也留在视野里（与 `/sr-gdd-ue` 的宣讲版式同一个用意）。**页面上只有一种编号**：定稿标题自带的 § 章节号；am 原版会给面板自动分配字母（A/B/C），两套编号叠在一起（`G · §4.4 R4 战斗`）对读者毫无作用，**本 skill 内置的 am 已经不产出它**。**目录跟着读**：左侧目录自己滚，并且**当前正在读的那一节在目录里高亮**（长文档里读者要一眼知道自己读到哪）。这些项都做在**生成器**里——渲染出来即成品，没有第二步（见第 5 步）。

| | 本 skill（`_宣讲.html`） | `/sr-gdd-ue`（`_UE.html`） |
| --- | --- | --- |
| 受众 | 开会 / 评审的听众：策划、程序、测试、上级 | UE/UI 同事 |
| 范围 | **定稿 §1–§11 整份，一条不漏** | 只出 §5 界面与交互规则 |
| 形态 | 分节长文档（左侧目录、可搜索、可切主题） | 逐界面左图右文（对着做界面） |

**本 skill 不生产设计结论**。它只做呈现层的重排——规则、数值、契约、验收全部来自源定稿，一个字不加、一个数不改。**只接定稿**：还没有定稿时走 `sr-gdd-human`（写成稿）→ `/sr-config`（落配置）→ `sr-gdd-ai`（整合定稿）；定稿之后的改动走 `/sr-gdd-fix`。

### 渲染器（内置，MIT）

页面由 **`am`**（[answer-me-with-html](https://github.com/QingYunA/answer-me-with-html)，MIT）渲染：`resources/am/am.mjs`，单文件、零依赖、Node.js 20+，来源与 SHA256 见 `resources/PROVENANCE.md`。

**只写草稿，不写 HTML / CSS / SVG**——排版、配色、目录、主题切换、图示坐标全部由它负责。草稿是扩展 Markdown（`.md`），写法见 `references/draft-format.md`。

### 参考优先级

1. `references/draft-format.md`（定稿 → 草稿的映射规范，**本 skill 的执行依据**）
2. 用户当轮指定的参考样式 / 主题
3. 两者皆无时：`examples/合成示例/`（形态基准）

### 内容红线（越线即返工）

- **一条不漏**：§1–§11 有哪节出哪节，节内条目也不许因为"太细"而略过；判据是 `tools/cover_check.py`，未命中必须逐条处置；
- **不改写**：数值口径照抄（`表名.字段名`、"待配表"、"参考值 X，待定"），规则语义不动，定稿没写的结论一个字都不加；
- **只动表达层**：允许把长段落拆成短句、把 text 图转成流程组件、把表格换个排法——不允许增删信息；
- **不放过程留痕**：证据编号、假设台账、拍板记录属于成稿附录 A，定稿里本来就没有，更不该出现在页面上。

### 承载红线

- 图片一律 `data:image/...;base64,` 内嵌（`am` 自动做），保证单文件可独立打开、单独发送不丢图；
- **禁** `https://` 外链图与外部资源（`<link>` / 外链 `<script>` / `iframe`）——`tools/smoke_check.mjs` 会逐个点名；
- **禁**手写 `<style>` / 内联样式做版式；```html / ```svg 代码块是逃生口，只在没有任何组件能表达时用，且要在交付说明里讲清为什么。

## 使用方法

本 skill 是**用户调用型**（frontmatter `disable-model-invocation: true`）：只能由人输入 `/sr-gdd-html` 触发，agent 不会自动接手，也不进入面向模型的技能目录。

```
/sr-gdd-html <定稿路径或主题>
```

例如"把《英雄升级功能优化_定稿》出成给人读的 HTML"、"这份定稿太密了，出一版人读的"。

## 无输入时的行为

裸调用纪律见 `../sr-askme/references/bare-invocation.md`。本 skill 收集：

1. **源定稿**：要出 HTML 的那份**定稿** md（路径，或主题名由我从**本功能目录的 `gdd\`** 下定位 `_定稿.md`）；
2. **阅读范围**（可选，默认 §1–§11 全出）：本次只出哪几节（如"只给程序看，§6–§10 就够"）；
3. **界面图目录**（可选）：§5 各界面若有截图，一并内嵌；没有就保留定稿原有的 ASCII 线框图。

用户补齐后再从第 0 步开始。

**输入守卫**：源文件不是**定稿**时停下，说明本 skill 只接功能 GDD 定稿，并指出该走哪一步——还没有定稿：`/sr-gdd-human` → `/sr-config` → `/sr-gdd-ai`；已有定稿但要改内容：`/sr-gdd-fix`。**不静默加工非定稿材料**——成稿、体验报告、复刻规格、评审意见、会议纪要等一律不做。

## 路径约定

`<SR_WORKSPACE>` / `<SR_PROJECT>` 取自 `%USERPROFILE%\.dsh\sr-workbench\config.local.json`；字段缺失、为空或路径失效时运行 `/sr-askme` 补齐；成组安装见 `../sr-askme/SKILL.md` §四。

本 skill 自身资源以**相对路径**引用（`resources/am/am.mjs`、`tools/cover_check.py`、`references/draft-format.md`），保证 skill 目录可整体搬迁。

## 执行流程

### 第 0 步 · 载入项目语境

读 `../sr-askme/references/sr_project_context.md`，遵守其中的数值铁律与写作约束（中文、术语与项目代码命名一致、gdd 不出现代码/技术选型细节、区分 RPG 战斗与 SLG 战斗）。

数值铁律在本 skill 下的执行方式：**页面上每一个数值都照抄源定稿的写法**——定稿写 `表名.字段名` 的照写，写"待配表"的照写，写"参考值 X，待定"的照写；本 skill 不新增、不换算、不补全、不四舍五入。
完成判据：页内每个数值都能在源定稿中找到**同一写法**。

### 第 1 步 · 输入确认

定位源定稿，先读头部 `doc_type` + `status`：`doc_type: final_gdd` 是正常输入，其中 `active` 按正常流程处理、`provisional` 允许继续（页头 `source` 行必须显式写"工作版，非正式定稿"）、`blocked` 直接停止并报告阻断原因、`pending` 说明定稿还没过门（建议先走 `/sr-gdd-review`，用户坚持要出就照出并在页头标注）；**其余情况**（`doc_type: draft_gdd`、无头部字段的旧文档）说明这不是定稿，按「输入守卫」停下并给出去路。随后确认三件事，缺一即问用户，不自行假设：

| 项 | 内容 |
| --- | --- |
| 源文件 | **定稿**路径 + 版本/日期（同名多版本时以用户指定为准，不默认取最新） |
| 阅读范围 | §1–§11 全出，还是本次只出某几节 |
| 界面图目录 | §5 有没有现成截图可用；没有就保留定稿的 ASCII 线框图 |

完成判据：源文件、头部两字段、阅读范围、界面图目录四项明确；非定稿已停下并给出去路。

### 第 2 步 · 信息盘点（不漏信息的基线）

先把定稿的**信息锚点**列出来当基线——这是后面"一条不漏"的判据来源：

```bash
python <skill>/tools/cover_check.py --gdd "<定稿.md>" --list
```

它抽四类锚点：**章节标题**、**表格每一行的首列**（规则名 / 界面名 / 字段名 / 键名 / AC 编号…）、**反引号里的标识**（`表名.字段名`、文件名、枚举值）、**Rn / UEn / ACn 编号**。

看着这份基线过一遍定稿，确认三件事，缺一即问用户：

| 项 | 为什么问 |
| --- | --- |
| 定稿有没有**空节 / 占位节**（"待补"） | 空节照出会让人以为漏了；要么照实标"待补"，要么先走 `/sr-gdd-fix` 补上 |
| 有没有**不该外发**的内容（内网地址、未公开数值、他人姓名） | 本页默认是"发给人看"的，外发前必须确认 |
| §5 各界面**有没有图** | 决定页面上是内嵌截图还是保留 ASCII 线框图（两者都要留，不能丢） |

完成判据：基线已产出；空节、敏感内容、界面图三件事都有结论。

### 第 3 步 · 写草稿（定稿 → 扩展 Markdown）

按 `references/draft-format.md` 的**逐节映射表**把定稿整份写成草稿：一个章节一个面板、长表格留住、流程与状态改用 `flow` / `sequence`、界面图用 `![说明](绝对路径)`、ASCII 线框图原样贴进 `text` 代码块。

写法要点（完整规范见同一文件）：

- `template` **固定 `doc`**（定稿是长文档，要按顺序读；`doc` 自带左侧目录）；`theme: auto`；
- **面板标题保留定稿章节号**（`## §4.1 R1 升级条件`）——读者对着定稿回查时，编号是唯一可靠的锚；
- **能用表格就别用图，能用内置组件就别写 HTML**；组件语法现查现用，不要凭记忆写：

  ```bash
  node <skill>/resources/am/am.mjs list          # 模板 / 主题 / 组件
  node <skill>/resources/am/am.mjs help <组件>   # 某个组件的语法
  ```

- 正文按 STE 中文纪律写（一句一事、步骤 ≤35 字、描述 ≤45 字、不用轻动词与模糊量词），`am render` 会自动检查；
- 定稿缺哪一节就少哪个面板——不硬凑、不补写；但**定稿有的必须都有**。

草稿落到 `<功能目录>\gdd\<主题>_宣讲.md`（**它同时是重渲与 `am patch` 局部改的源**）。
完成判据：§1–§11（或用户指定的范围）每节都有对应面板；无外链、无生图、无自造结论、数值写法与定稿一致。

### 第 4 步 · 校验（文风 + 不漏信息，两关都过）

```bash
node <skill>/resources/am/am.mjs lint "<草稿.md>"                            # STE 文风
python <skill>/tools/cover_check.py --gdd "<定稿.md>" --draft "<草稿.md>"     # 不漏信息
```

- `am lint` 报 `STE n warnings`：按提示改写后重跑，**最多两轮**；两轮后仍有警告，保留页面并在交付说明里如实讲。
- `cover_check.py` 报**未命中**：这就是漏信息，**每一条都要处置**，二选一——① 确实漏了：补进草稿重跑；② 确实不需要单独出现（被合并进一句话、或作为表头出现）：在呈给用户的报告里**写明理由**，不许沉默略过。
- `cover_check.py` 报**部分命中**：关键词没全对上，逐条人工确认是不是换了个说法。

它查不出"语义被改写"——所以还有一条人判据：**页面上任何一句话，都要能在定稿里找到出处**。
完成判据：`cover_check.py` 退出码 0（无未命中）；STE 警告已处置或已在报告里说明；所有"部分命中"已人工确认。

### 第 5 步 · 渲染

```bash
node <skill>/resources/am/am.mjs render "<草稿.md>" -o "<功能目录>\gdd\<主题>_宣讲.html" --no-open
```

**必须带 `-o`** —— 不带的话页面会写进 `~/.answer-me-with-html/pages/`，不进功能目录、也不进面板的产物分类。渲染器报错（`✗ L<行> [组件] …` 并给出正确示例）时**先修草稿、不手改 HTML 输出**——HTML 是派生物，任何内容修订都回到草稿重跑。

**一条命令就够，没有第二步。** 宣讲稿的四项版式全在**内置的 am 里**（`resources/am/am.mjs`；本项目对它的改动、以及为什么改在生成器而不是渲染后，见 `resources/PROVENANCE.md` 的「本仓库这一份是 fork」）：

1. **面板不再有字母 ID**——定稿标题已经带着自己的 § 章节号，am 原版还会给每个面板套一个字母（头部一个方块 + 左侧目录一个 `G · ` 前缀），两套编号叠在同一行纯属噪音；现在**生成时就不产出**；
2. **界面图与规则并排、图吸顶**——规则再长，图也留在视野里（对着图读规则）；
3. **左侧目录自己滚**——宣讲稿动辄 20+ 个面板，目录比视口高时 sticky 留不住它，会跟着正文走、读者点不到下面的章节；
4. **目录标出当前章节**——滚动时把正在读的那一节在目录里高亮（加粗 + 强调色左边线），并把该项滚进目录可视范围，读者一眼知道自己读到哪。

**改在生成器里，不只是少敲一条命令**：`am render` 与 `am patch` 都是**整页重渲**（用 am 重新生成整个 HTML 并覆盖同名文件），"渲染后再回头改 HTML"的补丁每次都会被冲掉——实测跑一次 `am patch` 只改一个面板，页面立刻回到 30 处字母、样式块消失。现在没有这个耦合了。

完成判据：HTML 落盘，渲染器回报的面板数与草稿一致。

只改一个面板时不要整页重写（草稿里的 `##` 面板与页内 `#am-source` 一一对应）：

```bash
node <skill>/resources/am/am.mjs patch "<输出.html>" --panel "<面板标题>" --from "<新面板.md>"
```

### 第 6 步 · 轻量视觉冒烟（每次必检）

九项每次必过，**并以无头浏览器实际渲染确认**——只读 HTML 源码不算通过：

- [ ] 无破图（每张图解码成功）
- [ ] 无横向溢出 / 重叠
- [ ] 图片全部 `data:` 内嵌（外发不丢图）
- [ ] 无外部资源引用（离线可打开）
- [ ] 面板数 > 0，目录锚点逐个可用
- [ ] 草稿源已内嵌（`#am-source` 在，页面可 `am patch` 局部改）
- [ ] **界面节的图真的吸顶**（实测：滚进长界面节后图仍在视口里，不是"声明了 sticky"就算）
- [ ] **面板字母 ID 已清**（头部方块 + 目录前缀都不在了；定稿自带的 § 编号是页面上唯一的编号）
- [ ] **左侧目录能自己滚**（实测：滚到文档中部时目录仍在视口里；它比视口高时会跟着正文走、点不到下面的章节）

**第 7–9 项同时是「内置的 am 确实是本 fork」前三处改动的判据**：它们红了，多半是 `resources/am/am.mjs` 被换成了上游原件（hash 见 `resources/PROVENANCE.md`）。**第 4 处改动「目录标出当前章节」的判据还没进这份清单**（见 `resources/PROVENANCE.md` 的改动点 4）。

```bash
node <skill>/tools/smoke_check.mjs --html "<输出.html>" --out smoke.png
```

**视口高度是判据的一部分**：默认 `--height 900`（贴近真实阅读视口）。**别用大视口测**——目录 35 个面板时约 1045px 高，在 1200px 视口里塞得下、第 9 项什么都测不出来，而真实的 ~900px 视口里它就超高、sticky 失效。换屏幕测：`--height <你的浏览器内容区高度>`。

**退出码非 0 即不予交付。** Node 不可用时的降级路径：

```bash
# Chrome / Edge 无头截图（路径含中文时先复制到 ASCII 路径）
chrome --headless=new --disable-gpu --window-size=1440,6000 --screenshot=smoke.png "file:///<输出.html 的绝对路径>"
```

**无论哪条路径，最后都要人眼过一遍截图**（工具判"结构没坏"，判不了"读起来顺不顺"）。发现问题改草稿重跑；修复后重检。无需全页面逐屏验收。
完成判据：九项全过，且截图已目视复核（不是"看起来应该没问题"）。

### 第 7 步 · Human Gate

向用户呈现**宣讲稿 HTML、覆盖核对结果与自查结果**，等待选择：

```
approve / revise / resupply_screenshots / reject
```
完成判据：用户已从上述选项中明确选择其一；**用户没表态之前不许替他写任何决策** —— 但用户每给一次拍板或纠偏，就按 `../sr-askme/references/decision-recording.md` 当场追加一条（门内迭代也各记一条）。

（本 skill 不设 `request_missing_evidence`——缺材料在第 1/2 步已问过。）

- `revise`：按意见改草稿，重跑第 4–6 步；
- `resupply_screenshots`：换/补界面图后重跑第 3–6 步；
- **任何出口**都按 `../sr-askme/references/decision-recording.md` **追加一条决策记录**：`**决策**：` 写这次拍板（approve / reject / revise / resupply_screenshots）与宣讲稿的结论；未命中 / 部分命中的处置理由写进同一条的正文。

### 外发前要知道的三件事

1. **页面里留着图片的原始路径**（`<img data-am-src="…">` 与内嵌草稿里的 `![](...)`）——这是 `am` 为了让 `am patch` 能重新读图而保留的，**不上屏**，但源码里能看到本机目录结构。发给团队外的人之前先确认这一点可接受（要剥离就另存一份删掉 `data-am-src` 与 `#am-source` 的副本，并说明那一份不能再 `am patch`）。
2. **页面体积 ≈ 全部截图之和**：§5 界面图多时会到几十 MB，走文件传输，不要用聊天工具贴。
3. **页面自带署名链接**：页脚 colophon 里有渲染器上游仓库地址（MIT 的署名要求）；它不外链任何资源，离线可打开。
