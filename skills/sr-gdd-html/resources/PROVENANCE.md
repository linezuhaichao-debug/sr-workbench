### 为什么 fork（而不是"渲染后再改 HTML"）

这四件事**本该是生成器的逻辑**。做成后处理有两个真问题：每一步要跑两次（渲染 + 补丁），而且 **`am patch` 一重渲就把补丁冲掉**（实测：只改一个面板，页面立刻回到 30 处字母、样式块消失）。所以直接改在 am 里，一条 `am render` 到位。

### 改动点 1 · 面板头部不再输出字母方块

`render` 里那一处：`<header class="am-panel-head"><span class="am-panel-id">…</span><h2>…` → 去掉那个 `<span>`。

理由：宣讲稿的面板标题**已经带着定稿自己的章节号**（`§4.4 R4 战斗`），am 再套一个字母（头部一个方块 + 目录里一个 `G · ` 前缀）＝**两套编号叠在同一行**，对读者毫无作用、纯噪音。

### 改动点 2 · 左侧目录只输出标题

`const toc = …` 里 `` `${esc(p.id)} · ${esc(p.title)}` `` → `` `${esc(p.title)}` ``。

同上的另一半。**这一处在后处理里删不掉**：字母和标题是 am 拼成的**一个文本节点**，CSS 够不着——只有生成时不拼它才行。

### 改动点 3 · `BASE_CSS` 末尾追加一段 SR 定制样式

- `.am-panel-head { padding-inline-start: 14px }` —— 补回改动点 1 让出来的左内边距；
- `.am-toc { max-height: calc(100vh - 48px); overflow-y: auto; … }` —— **左侧目录自己滚**：宣讲稿动辄 20+ 个面板，目录比视口高，而 **sticky 留不住比视口高的元素**，它会跟着正文往下走、读者点不到下面的章节（实测反馈）；
- `.am-panel:has(.am-md > .am-figure ~ *) { overflow: visible }` 与 `.am-md:has(> .am-figure ~ *) { … }` —— **界面图与正文并排、图吸顶**（对着图读规则）。两条**必须如此**的实测理由：图要受视口高度约束（`46vh`），否则竖屏界面截图比右栏还高、sticky 的可用行程是 0；`.am-panel` 自带 `overflow: hidden`，它是 sticky 的裁剪祖先，不放开就**完全吸不住**。

四处都带 `★★ SR 定制（sr-gdd-html）★★` 注释，合并上游时按这个标记找；改动点 4 的 JS 那半在 `RUNTIME_JS` 末尾，锚点是注释行 `// ④ 目录标出`（它不在上面那段 CSS 注释块里）。

### 改动点 4 · 左侧目录标出「正在读的章节」（2026-10-13 加）

两处：

- CSS（追加在 `★★ SR 定制` 块的 ④ 行）：`.am-toc a.am-toc-current { color: var(--ink); font-weight: 600; border-inline-start-color: var(--accent); }`；
- JS（追加在 `RUNTIME_JS` 末尾、`})();` 闭合之前）：一个自包含 IIFE —— 取 `.am-toc` 的锚点与对应面板，滚动时把「最后一个越过页面上沿 88px 的章节」标成 `.am-toc-current`（只留一个）；目录自身比视口高时，还把当前项滚进目录可视范围（只改目录的 `scrollTop`，不动页面滚动）。

理由：**目录能滚 + 能点，但读者不知道自己读到哪一节**——35 个面板的长文档，没有"当前章节"反馈时，左侧目录只是一个跳转列表（实测反馈：目录改成可滚动之后，读者问"当前看的章节选中效果呢"）。这一处与改动点 3 的 `.am-toc` 滚动是**一对**：目录会滚，才更需要"当前项自动可见"。

★ 它**不是**某个旧功能的回归——本 fork 与上游 0.4.15 都没有过当前章节高亮（`IntersectionObserver` / `is-active` / `aria-current` 三者在 fork 前的渲染产物里都是 0 处），这一处是新增。

### 改动点 5 · 页面铺满视口宽度（2026-10-16 加，来自用户反馈）

`BASE_CSS` 里原生那条 `.am-doc { max-width: 1120px; margin: 0 auto; }` 被 SR 定制块末尾的 `.am-doc { max-width: none; }` **覆盖**（不改原句，便于上游升级时重放）。

理由：宣讲稿是**对着图 + 表**读的。用户视口约 1550px 时，1120px 居中 ⇒ **两侧各空 213px（占屏幕 27%）**，而右边的表格、界面图同时被挤窄。实测 1920px 视口下：改前内容宽 1120px（两侧各空 400px），改后 1920px（零留白）。

### 改动点 6 · 界面图列宽与限高各 ×1.5（2026-10-16 改，**属于改动点 3 那两条规则的值**）

`grid-template-columns: minmax(200px, 300px)` → `minmax(300px, 450px)`；`.am-figure img` 的 `max-height: 46vh` → `69vh`。

理由：用户反馈"界面流程里的图占的位置太小，图上字小得看不清"。**两处必须一起改**——界面截图是 2160×3840（9:16）竖屏图，在 450px 列宽下 **限高才是真正卡住尺寸的那个约束**（450 × 16/9 = 800px），只放宽列宽的话图仍然被 46vh 卡住、一个像素都不变大。

实测（合成示例 840×1800 的占位图，视口 1600×900）：改前 173×370 → 改后 260×555，**正好 1.5 倍**。
实测（《联盟讨伐》2160×3840 界面图，视口 1920×1080）：**420×745**（限高 745px = 69vh）。

★ 代价要说清：图高了，"图吸顶"时留给右栏规则的空间就少（1080 视口下 745px 图 + 面板头 ≈ 占满一屏）。
实测中若右栏内容比图短，吸顶行程就是 0 —— 那不是 bug（图本来就在视野里），`smoke_check` 第 7 项会把这种情况报成 `[--] 不适用`。**看不清的小字由此改走改动点 7 的"点图看原图"**。

### 改动点 7 · 点图放大看原图（2026-10-16 加）

两处：CSS（追加在 `★★ SR 定制` 块的 ⑦ 段）与 JS（追加在 `RUNTIME_JS` 末尾，锚点注释 `// ⑦ 点图放大看原图`）。
交互：点正文大图（原始宽 ≥200px）→ 全屏看原图；可翻页（‹ ›/←→）、切"适应窗口 / 1:1 原始像素"、按 1.25 步进缩放（−/+ 或键盘）、Esc 或点遮罩关闭。

★ **类名一律用 `am-imgzoom*`，刻意不叫 `.am-lightbox`**：那个名字是**上游 am 自带的图表查看器**（`.am-lightbox` + `.am-lightbox-stage/canvas` + `.am-diagram-expand` 按钮，给 flow / sequence 这些 SVG 图做平移缩放，CSS 是 `display:flex` + `[hidden]`）。第一版撞了名，后果是 CSS 里那条 `.am-lightbox { display: none }` **把上游图表查看器整个压成不可见**——所以这里的判据是"上游那套仍然好使"：`tools/smoke_check.mjs` 之外，验证时要点开一个 `.am-diagram-expand` 看还能不能展开。

两个细节都是实测踩出来的，改的时候别退回去：
1. **懒建**：查看器在**第一次点击时**才 append 进 DOM。常驻的话，页面里永远躺着一个 `<img class="am-imgzoom-img">` 没有 `src` —— 在冒烟里就是一张**破图**（第 1、3 项直接红）；
2. **关闭时整个移除**（不是 `display:none`）：同理，不留没有 `src` 的 `img`；`smoke_check` 第 12 项会查这一条（`boxRemoved`）。

另外底栏与关闭按钮用**深色底 + `backdrop-filter`**：它们压在**任意一张截图**上，第一版用白底白字，在浅色界面上等于看不见（1:1 看原图时最明显）。

### 为什么不整包安装、而是内置单文件

上游 `answer-me-with-html` 是一个**技能包**（SKILL.md + references + scripts）。本 skill 只借它的**渲染器**，不借它的技能语义（"把一次回答画成一页"是另一回事，不是 GDD 的职责）。所以只内置 `scripts/am.mjs` 这一个文件 + LICENSE：

- 它是**单文件、零依赖**的 CLI，拷进来就能跑，同事装策划工作台插件即完整可用（不需要自己装 answer-me-with-html）；
- 版本、字节数与 hash 都记在这里；上游若改了页面语汇，本 skill 的 `references/draft-format.md` 要跟着复核一遍（组件的**最小语法**在那里有示例）。

### 上游更新时（**要重放这几处改动**）

1. 取到新版 `am.mjs`，先看版本号与 CHANGELOG（上游仓库）；
2. **不要直接覆盖** —— 按上面七个改动点把我们的改动重放到新版上。锚点：
   - 改动点 1：`am-panel-head` / `am-panel-id`（`render` 里那一处）；
   - 改动点 2：`const toc =` 里 `${esc(p.id)} · ${esc(p.title)}`；
   - 改动点 3/5/6/7 的 CSS：整段追加在 `BASE_CSS` 末尾（`★★ SR 定制` 注释块），其中 ⑥ 是**改块内那两条规则的值**（`minmax(300px, 450px)` 与 `max-height: 69vh`），⑤ 是块里那条 `.am-doc { max-width: none; }`；
   - 改动点 4/7 的 JS：追加在 `RUNTIME_JS` 末尾、`})();` 闭合之前（锚点注释 `// ④ 目录标出`、`// ⑦ 点图放大看原图`）；
   - 全文搜 `SR 定制`、`am-imgzoom`、`am-toc-current` 可定位全部改动；
3. 更新本文的**上游版本**与两个 SHA256 / 字节数；LICENSE 若有变，一并替换；
4. 跑 `examples/合成示例/` 的复现命令 + `tools/smoke_check.mjs` —— **第 7–12 项分别是改动点 3/1+2/3/5/6/7 的判据**（第 7 项＝图吸顶与视口限高，第 8 项＝去字母，第 9 项＝目录独立滚动，第 10 项＝铺满，第 11 项＝图 ×1.5，第 12 项＝点图放大）；
5. 抽查 `references/draft-format.md` 里引用的组件最小语法（`am list` 与 `am help <组件>` 对一遍）。

## 复现命令

```bash
node resources/am/am.mjs render "examples/合成示例/draft.md" --no-open -o "examples/合成示例/01_宣讲稿_示例.html"
node tools/smoke_check.mjs --html "examples/合成示例/01_宣讲稿_示例.html" --out smoke.png --width 1600 --height 900
```

**渲染一条就够**：去字母、图吸顶、目录独立滚动、铺满、图 ×1.5、点图放大都在 am 里，没有第二步。
冒烟第 10 项要在**视口宽 > 1140px** 下才测得出（小于就本来就铺满），所以复核时用 `--width 1600`。

## 本 fork 的三处改动是怎么改进去的

`BASE_CSS` / `RUNTIME_JS` 都是**单行字符串字面量**，手改容易破转义。两次改动用的都是一次性脚本：
把要插入的 CSS / JS 写成普通源文件（`insert.css` / `insert.js`），脚本读进来转义后**追加到字面量末尾**（值调整则做唯一性断言后的替换），再 `node --check` + 跑示例渲染确认。
脚本用完即弃、不随 skill 留档——**要复刻就照上面「上游更新时」重放**，别指望脚本还在。

## 日常用法（本 skill 只用到这几条）

```bash
node <skill>/resources/am/am.mjs render <草稿.md> -o <输出.html> --no-open   # 渲染（版式与去字母都在里面）
node <skill>/resources/am/am.mjs lint   <草稿.md>                            # 只跑 STE 文风检查
node <skill>/resources/am/am.mjs patch  <输出.html> --panel "<面板标题>" --from <新面板.md>   # 只改一个面板，原地覆盖
node <skill>/resources/am/am.mjs list                                        # 模板 / 主题 / 组件清单
node <skill>/resources/am/am.mjs help <组件|format|image|code>               # 某个组件的语法
```

`am render` 默认把页面写进 `~/.answer-me-with-html/pages/`；本 skill **一律用 `-o` 指定到功能目录**（见 `SKILL.md` 的「产出规范」）。渲染器只读草稿与图片，不写别处。
