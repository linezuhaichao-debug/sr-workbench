## 7. 多语言文本

> 只列**普通文本**（文本表里可增删改的那些条目）。GID 名称/描述键 `n{gid}`/`d{gid}` 随配置表的 gid 走，不在此列。
>
> **形状**（本节说明**供撰写参考，不写入定稿** —— 定稿只保留范围声明、表格与表级核验注）：基准八列 `键 / 中文文案 / 占位符 / 状态 / UI位置 / UI状态 / 触发 / 用途`，**列名与列序逐字照此**；**键名未核验 / 未定的功能在第 2 位增列 `候选Key名` 成九列**（键名已全部核验的不增列）。列与下游「正式 AI读版 · 多语言引用」逐列对齐，转置零推断。逐列口径：
> - `键`：**只放已核验的官方键名**；键名已定但尚未落表核验的，写键名并在 `状态` 列标 `已提供Key-未核验` 或 `新增需求`；**键名未定写 `待分配Key`**。
> - `候选Key名`：键名未核验 / 未定时填本功能建议的键名（落表查重通过后才升级为官方键）；本列无候选名时写 `—`。
> - `占位符`：紧跟 `中文文案`，写 `$0＝<含义>（来源：<表名.字段名 / 服务端字段>）`，多个用 `；` 分隔，**可选占位符在含义后标「（可选）」**（统一 `$0` / `$1` 形式；无占位符写 `—`）。
> - `状态`：**注册词表取值，不得自造** —— `新增需求` ／ `修改需求` ／ `已提供Key-未核验` ／ `已核验Key` ／ `建议复用` ／ `待分配Key` ／ `本功能不再引用` ／ `待确认` ／ `不纳入AI读版`。
> - `UI位置`：文案落在哪个界面/控件（写界面名 + 控件，不用"弹窗里"这类模糊说法）。
> - `UI状态`：工程枚举之一 —— `available` / `unavailable` / `confirmation` / `success` / `failure` / `empty` / `waiting` / `cooldown` / `reward` / `cost` / `settlement`。
> - `触发`：这条文案**什么时候出现**（条件 / 时机）。
> - `用途`：这条文案**干什么用**（语义角色 / 玩家后果）—— 与 `触发` 不同，例：触发＝`次数为 0 时点击`，用途＝`次数耗尽的拒绝反馈`。

| 键 | 中文文案 | 占位符 | 状态 | UI位置 | UI状态 | 触发 | 用途 |

| <key> | <文案> | — / $0＝<含义>（来源：<表名.字段名 / 服务端字段>） | <注册词表之一> | <界面名·控件> | <枚举之一> | <什么时候出现> | <这条文案干什么用> |

> <表级核验注（表下必写）：键的落表与核验事实——文本源文件 + 条目数 + SHA256 + 核验结论。例：`本表 36 条已落表 normaltxt.xml（9137 条，SHA256 49350948…）并导出核验通过`。键尚未落表时写「键尚未落表，落表后回填核验证据」。**没有核验证据不得在 `状态` 列写 `已核验Key`**。>
