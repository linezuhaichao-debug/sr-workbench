# 产物历史版本（**改之前先存一版**）

> **用户口径（2026-10-12）**：**成稿 / 定稿 / UE 界面稿 / 宣讲稿 / 配置表**这几类，**每次改写之前**先把它当前的样子存一份，
> 命名 = **当前版名字后面追加 `_<YYYYMMDD>_<序号>`**，例如 `AI读版策划案_联盟讨伐_正式版_20261012_1.md`。
> 序号 = **当天该产物的第几份**，从 `1` 起。
>
> 判据一句话：**改写一个已经存在的产物之前，先把它当前的样子存一份。**

本文件是这条规则的**唯一权威**。各 skill 的正文与 persona 只写一行指针，不复制规则。

## 一、哪几类要存版（**只有这几类**）

| 产物 | **当前版**（固定名） | 历史版本 |
| --- | --- | --- |
| **成稿** | `gdd\<主题>_成稿.md`（**不带日期**） | `gdd\<主题>_成稿_<YYYYMMDD>_<N>.md` |
| **定稿** | `gdd\AI读版策划案_<功能名>_正式版.md`（**不带日期**） | `gdd\AI读版策划案_<功能名>_正式版_<YYYYMMDD>_<N>.md` |
| **UE 界面稿** | `gdd\<主题>_UE.html`（**不带日期**） | `gdd\<主题>_UE_<YYYYMMDD>_<N>.html` |
| **宣讲稿** | `gdd\<主题>_宣讲.html`（**不带日期**） | `gdd\<主题>_宣讲_<YYYYMMDD>_<N>.html` |
| **配置表** | `<config_root>\<表名>.xlsx`（程序按固定名读，**改不得**） | `<功能目录>\gdd\<表名>_<YYYYMMDD>_<N>.xlsx` |

★ **UE 界面稿是 2026-10-13 加进来的第 5 类**（`sr-gdd-html` 拆成 `sr-gdd-ue` + `sr-gdd-html` 时）：
它与宣讲稿同性质 —— 覆盖渲染、会被外发、别人拿去就用，所以同样**改之前先存一版**。
两份 HTML 各自的**源数据**（`<主题>_UE.content.json` / `<主题>_宣讲.md`）与 HTML **成对留档**：
HTML 存版时，同名的源数据一并按同一序号存一份（它们是复跑这一页的唯一依据）。

★ **找"当前版"时别把历史版本算进去**：`<主题>_<日期>_<序号>.<ext>` 是**留痕**，不是产物。
例如别把 `联盟讨伐_20261012_1.md` 当成"同主题的成稿" —— 成稿只有 `联盟讨伐.md` 那一份。
（判据：去掉全部扩展名后，尾部是 `_<8 位日期>_<序号>` 的一律是历史版本。）

★ **别的产物不在此列（但有例外）**（用户口径 2026-10-12，2026-10-16 修订）：`analysis\` 的分析产物（体验报告 / 问题卡 / 复刻规格 / 概念稿 /
旧文档分析 / 人工补充）、界面图、变更集、读回验收报告、修订点清单 —— **不要求**留历史版本；
**审查报告是例外**：日常复核 / 追加「改动后复核」节**直接改同一份**、不存版，但**结论发生变动**（如
「建议修复后交付」→「可交程序」、反向、或阻塞项数量增减）时，**改前先存一版**（`<同名>_<YYYYMMDD>_<序号>.md`）——
报告既是质量凭证也不外发，但结论翻盘时旧结论必须能翻回去查到（实例：`圣物系统_20261015_审查` 同日先出
「建议修复后交付」、修复后转「可交程序」，首审版已被覆盖，2026-10-16 补存 `_20261016_1`）。

### 为什么当前版**不带日期**

当前版名字里带日期的话，历史版本就会出现**两个日期**：
`AI读版策划案_联盟讨伐_20261010_正式版_20261012_1.md` —— 一个是产物身份（10-10 那版）、一个是存版时间（10-12 存的），
看着像重复。而**这四类产物本来就只有一份**（定稿只有一份、表只有一份），一个日期足够区分它们的历代版本。
所以：**当前版去掉日期，日期只出现在版本后缀里**。

例外说清楚：
- **这几类的名字都是「功能名 ＋ 类型后缀」**（`_成稿` / `_正式版` / `_UE` / `_宣讲`），**一律不带日期** ——
  用户口径 2026-10-12："成稿名字也改成 `功能名_成稿.md`，宣讲稿也是叫 `功能名_宣讲`，你倒是统一一下"。
  日期只出现在**历史版本后缀**里。
- **定稿是唯一带前缀的一类**（2026-10-28 口径）：它叫 `AI读版策划案_<功能名>_正式版.md` —— `AI读版策划案_` 是**类型前缀**，
  功能名在中间，`_正式版` 仍是类型后缀；历史版本 = `AI读版策划案_<功能名>_正式版_<YYYYMMDD>_<N>.md`。
- **定稿正文内联的图片不存版**（`gdd\assets\images\` 是图片位，不是产物）：图被换掉时**直接覆盖或改引用**，
  它的历代样子跟着那一版定稿的历史版本走（旧版定稿里引用的文件名保留即可）。
- **配置表**的当前版必须是程序读的那个固定名（`A079-联盟讨伐.xlsx`），**永远不能带日期**
  ⇒ 它只有"改前存旧版"这一条路，版本名 = `<表名>_<日期>_<序号>.xlsx`。

## 二、什么时候存

| 情形 | 存不存 |
| --- | --- |
| **改写一个已存在的产物**（改字段 / 改规则 / 改文案 / 改图 / 覆盖渲染…） | **存** —— 动笔**之前** |
| 首次创建（文件原本不存在） | 不存（没有旧版可存） |
| 只读、只打开、只重命名、只挪目录 | 不存（**改名不算内容改动**） |
| 配置表写入（`/sr-config` 经 Excel COM） | **引擎自动存**（见 §五），人不用管 |
| 历史版本文件本身再被改 | 不存（不给版本再开版本） |

**存的是"被替换掉的那一版"** ⇒ 任何时候都能退回上一版。
**不追溯**：本规则自 2026-10-12 起生效，以前的历代样子**不回填**。

## 三、命名

```
<当前版文件名去扩展名>_<YYYYMMDD>_<序号>.<原扩展名>
```

- `YYYYMMDD` = **存这一版的当天**。
- `序号` = **该产物在这一天的第几份**，从 `1` 起；由工具扫目录算，**不靠人记**。
- **不要**用「副本」「最终版」「v2」「new」「old」这类词，也不要把序号插在中间。

例（都在 2026-10-12 这一天存）：

| 当前版 | 第 1 份 | 第 2 份 |
| --- | --- | --- |
| `AI读版策划案_联盟讨伐_正式版.md` | `AI读版策划案_联盟讨伐_正式版_20261012_1.md` | `AI读版策划案_联盟讨伐_正式版_20261012_2.md` |
| `联盟讨伐_成稿.md`（成稿） | `联盟讨伐_成稿_20261012_1.md` | `联盟讨伐_成稿_20261012_2.md` |
| `A079-联盟讨伐.xlsx` | `A079-联盟讨伐_20261012_1.xlsx` | `A079-联盟讨伐_20261012_2.xlsx` |
| `英雄圣物_宣讲_20260923.html`（**覆盖渲染时**） | `英雄圣物_宣讲_20260923_20261012_1.html` | … |

★ **后缀加在"去扩展名"之后**：`x.content.json` 的版本是 `x.content_20261012_1.json`
（不是 `x.content.json_20261012_1`）。

★ **一个日期就好**：当前版不带日期 ⇒ 版本名里只可能出现**一个**日期。
（宣讲稿是唯一例外，见 §一 —— 那儿的第一个日期是**批次**，不是版本。）

## 四、落点

**产物所在的那个桶，平铺，不开子目录**（用户口径：「直接放到 `gdd\` 目录下就行」）：

| 产物在哪 | 历史版本放哪 |
| --- | --- |
| `<功能目录>\gdd\*` | **同一个 `gdd\`** |
| **`config_root`（`策划配置\`）里的表** | **该功能的 `gdd\`** —— ★ 例外：配置目录是程序运行时读的，多出来的工作簿会进导出 / `INDEX` / 引用扫描的视野 |

## 五、怎么存（用命令，别手工复制）

```bash
python "<sr-askme 技能目录>/tools/history_snapshot.py" "<产物绝对路径>"
```

- 它做的事：读目录实况算出下一个序号 → **复制**（`copy2`，保留时间戳）→ **打印新版本路径**。
- `--dry-run`：只算序号、只打印名字，**不复制任何文件**。
- `--dir "<目标目录>"`：换落点（**配置表**由引擎按 §四的例外传功能目录 `gdd\`）。
- 同一天同一产物反复调用会得到递增序号，**不会覆盖已有版本**。

## 六、谁来执行

| 场景 | 谁 |
| --- | --- |
| **改配置表**（`/sr-config`，经 Excel COM） | **写入引擎自动**：`plan.json` 带 `history_dir`，引擎在**验收通过之后**从改前副本派生一版 |
| **改成稿 / 定稿 / UE 界面稿 / 宣讲稿** | **本会话的 agent**：动笔（或覆盖渲染）之前先跑一次 §五 那条命令 |

> 存版本**不额外要用户确认**：它只是把当前状态留一份，不改内容、不删东西。

## 七、面板怎么显示它们（**要看得到**）

**历史版本要在「最终产物」里看得见**（用户口径 2026-10-12：
"我就是为了在最终产物里看历史版本才改这个的"）：

- 它**归它当前版所在的那一类** —— 定稿的旧版进「定稿」、表的旧版进「配置表」、成稿的旧版进「成稿」；
- 组内**当前版排第一**，它的历史版本按版本号**倒序**跟在后面；
- 组里**真有**历史版本时才加注：当前那份 `〔当前〕`、其余 `〔历史版本〕`（没有旧版的组一个注都不加）；
- 组说明（组头下那行小字）如实说"另有 N 份历史版本"。

判据**只有一份**（`sr-workbench/src/pure/buckets.ts`）：
`historyVersionOf` 认"去掉全部扩展名后尾部是 `_<8 位日期>_<序号>`"；
`currentNameOf` 把它**还原成当前版名字**；`outputGroupOf` 拿还原后的名字分类 ⇒ 自然与当前版同类。
（**没有这一步还原**，`AI读版策划案_联盟讨伐_正式版_20261012_1.md` 会掉进「其它」、`A079-联盟讨伐_20261012_1.xlsx` 会被当成另一张表。）

★ **它和「过程留痕」不是一回事**（别混）：变更集 / 读回验收报告 / 修订点清单仍然
**不列条目**，只在页签底部**报数** —— 那是"过程档案"，而历史版本是**产物本身的一代**。
审查报告**多数时候按过程留痕处理**（追加复核不存版）；只有**结论变动**那一次按上面的例外存版。

## 八、和"备份"不是一回事（两个都要有）

| | `.backup.<时间戳>` | **历史版本 `_<日期>_<序号>`** |
| --- | --- | --- |
| 谁产生 | 写入引擎（自动） | 引擎自动 + agent 手动 |
| 用途 | 验收对比、**失败回滚**（一次性） | **累积留档**、随时退回上一版 |
| 落点 | 目标表同目录 | 产物所在桶（既有表 → 功能目录 `gdd\`） |
| 保留 | 可随时清理 | **保留** |
| 参与配置扫描 | **不参与**（名字含 `.backup.`） | **不参与**（名字尾部是 `_日期_序号`） |

两者**互为补充**：`.backup.` 管"这次写入别写坏"，历史版本管"上一次长什么样"。
