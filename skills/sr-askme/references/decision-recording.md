# 决策记录写入规范（decision-recording）

本规范是**全系列唯一一份**决策写入口径。它管一件事：**一个功能的所有决策，都追加进同一个文件**。

## 一、文件在哪（一个功能**只有一个**决策文件）

```
<功能目录>\decisions\决策记录.md
```

`<功能目录>` 按下面顺序认：

1. **当前会话的工作目录就是功能目录**（`features\<主题>\`，从策划工作台进来的会话都是这样）⇒ 就是 `<cwd>\decisions\决策记录.md`；
2. 否则从 `<SR_WORKSPACE>` 找：`<SR_WORKSPACE>\features\<主题>\decisions\决策记录.md`（`<SR_WORKSPACE>` 见 `../config.local.json`）；
3. 都认不出来（既不在功能目录里、也不知道主题）⇒ **先问用户是哪个功能**，别猜、别往别处写。

`decisions\` 目录不存在就直接创建。**不再有** `decision_<主题>_<日期>.json`、**不再有**按日期分文件、**不再有** `decision_id` / `status` 枚举 / 16 个必填字段 —— 那些口径已废弃，见到旧文件也不要往里加东西（旧文件是历史留痕，就地留着）。

## 二、什么时候写（**不是只在 Human Gate**）

只要**定下了一件事**就写一条。包括但不限于：

- Human Gate 上的拍板（选定方向、approve / revise / reject）；
- 选了 A 方案而放弃 B；
- 改了某个口径、数值、命名、边界（明确"什么不做"）；
- 确认了一条来自素材 / 竞品 / 旧文档的结论（它改变了后续做法）；
- 决定先做哪一步、暂缓哪一步；
- 纠正了之前的一个判断（**新写一条**说明改了什么，不要回头改旧条目）。

判据只有一句：**这件事如果以后有人问"当时为什么这么定"，这条记录要能回答。**
拿不准要不要记时 —— **记**。

纪律：

- **Gate 之前**的迭代循环里，用户每给一次拍板 / 纠偏，就要追加一条（这就是"所有决策"的含义；不要攒到最后一起写）。
- **只在文件末尾追加**，绝不修改、删除、重排已有条目。
- 不新建第二份决策文件。

## 三、怎么写（格式）

文件不存在时，先写标题行：

```markdown
# 决策记录 · <功能主题>
```

然后每条条目：

```markdown
## 2026-10-08 14:23:05
**决策**：采用方案 A —— 联盟成员共享 BOSS 血量。
**依据**：上一轮访谈三个人都提到一个人打全盟看不到。
**影响**：§4 R2 的血量口径要改；BOSS 表要加一列。
```

- 标题行必须是 `## YYYY-MM-DD HH:mm:ss`（**年月日时分秒**，24 小时制）。
  也可以写成 `## 2026-10-08 14:23:05 · 一句话标题`。
- **时间取当前本地时间到秒**，用命令取、不要自己推算：
  `Get-Date -Format 'yyyy-MM-dd HH:mm:ss'`（PowerShell）/ `date '+%Y-%m-%d %H:%M:%S'`（bash）。
- `**决策**：` 那一行是**必须**的；`**依据**` / `**影响**` 选填，但能写就写。
- 正文其余部分自由（可以带 `-` 列表、可以带条目引用），但**别放长论证**——这一份是给人读的时间线，不是聊天记录。
- 同一秒可以有多条；顺序就是时间顺序。

## 四、写完要说

在回复里带一句：`已记进决策记录：<时间> · <一句话>`（例：`已记进决策记录：2026-10-08 14:23:05 · 采用方案 A`）。

不要问用户"要不要记"、不要等用户说"记一下" —— **按本规范直接记**。

## 五、策划工作台怎么用它（用户视角）

工作台功能详情里的「决策记录」模块就是把这**一个文件**读成时间线（最新的在最上面）。
所以：文件里有什么，用户就看到什么；**没写进去的决策等于没发生过**。
面板是只读的——它不会替你补写，也不会替你创建这个文件。

## 六、与校准流水的区隔

`evidence\calibration_<主题>.jsonl`（见 `calibration-recording.md`）是 Gate 前迭代的**机器流水**，
它是证据、不是决策记录。决策记录里那一条**人话**才是权威结论；校准流水不往决策文件里搬内容，
两者时机不同、职责不同、互不替代。
