# UI 效果图核对（截图对照）操作手册

代码核查回答「有没有做」，这一节回答「长得对不对」。两者都是同一个包的核查产出，共用一套编号和同一张对照页。

## 什么时候跑

需求包目录里能找到效果图（`UI效果图/`、`设计稿/`、`UI图/` 之类），就跑；找不到就跳过，并在报告里写一句「本包无 UI 效果图，未做界面外观核对」。

跑之前**代码核查必须已经做完**：先知道哪个面板对应哪个界面，截图时才不会漏屏。

---

## 第 1 步 找效果图，先看清有几张

扫包目录（`srrequirement/下游包/<需求名>/<版本>/`）下所有子目录，凡是扩展名为 png/jpg/webp/jpeg 且所在目录名带「效果图 / UI图 / 设计稿 / mock」的，都算效果图。

同一个界面常同时存在两套文件名：

- 语义名：`圣物装配.png`、`抽卡结果.png`
- 交付名：`IMG-002__02_圣物-装配.png`

**按文件大小去重**，大小相同的两组是同一张图；以语义名为准做配对键。

动手前先把清单摆给用户：

| 序号 | 效果图文件名 | 画面内容 | 对应工程界面 |
| --- | --- | --- | --- |
| 1 | `圣物装配.png` | 装配页三页签 | `UI_HeroicRelic_Equipment` |

画面内容看不出来时（文件名是 `IMG-001` 这种），直接看图再填。

## 第 2 步 建收图目录与命名清单

在版本目录下建：

```
<版本>/UI对照/
    _收图说明.md          # 给用户的截图清单（见下）
    工程截图/              # 用户放图；命名与效果图同名
    标注/                  # 生成物：标注图
```

`_收图说明.md` 固定四段：

1. **配对清单**表格：`# | 效果图文件名 | 需要截的工程界面 | 备注`
2. **截图要求**：只要游戏画面本体，不要编辑器边框/黑边；尽量 1080×1920；尺寸不限，脚本会自动缩放对齐
3. **不用对齐的部分**：列表内容、数量、星级、品质色这类代码生成的数据不同属正常，只看 UI 样式
4. **缺图怎么办**：打不开或没做的，直接说文件名

命名规则一句话说清：**文件名与效果图完全一致**。

## 第 3 步 提示用户收图

把清单发给用户，并主动说明三条，避免来回：

- 竖屏 9:16，画质越高越好；带编辑器边框的图我会裁掉，但截干净更快
- 内容生成的差异不用管，只看样式
- **同版式不同配色的弹窗只截一张**（例如四品质详情只换底图），其余复用同一结论

用户说「已放入」后先跑一遍核对：文件名、分辨率、缺失项，把缺的列出来再开工，不要默默按现有图硬对。

## 第 4 步 逐屏对比

一屏一屏看，**先结构后样式**：

1. 结构：有哪些区块、区块顺序、哪个在上哪个在下、缺了哪块
2. 元素：角标、图标、按钮、开关、进度条，在不在、位置对不对
3. 样式：底色、描边、字号、字色、圆角、对齐方式、层级（有没有被遮罩压暗）
4. 文案：标题、页签、按钮、提示语的措辞与格式

判定纪律：

- **数据不算差异**：列表条目数、星级、数量、战力数值、品质色不同，都不是问题。
- **状态不算差异**：可激活/已激活、已装备/空槽，只要样式一致就不算。
- **效果图是占位稿时不要硬对**：按钮写 `Confirm`、正文写「文本内容描述」、标题写「系统标题」，这类是设计稿占位，工程有中文是正常的。
- **拿不准就标「待确认」**，写清哪两种可能，交给策划裁决，不要替策划选。

## 第 5 步 分类：六类，一类一张图

| 类别 | 判据 | 例子 |
| --- | --- | --- |
| 多余元素 | 效果图没有、工程多了 | 顶部资源栏、未上阵提示条、属性行虚线 |
| 缺失元素 | 效果图有、工程没有 | 跳过动画勾选、可升级角标、数量角标 |
| 样式差异 | 位置都在，长得不一样 | 等级无底块、NEW 角标居中、卡片白灰渐变 |
| 布局差异 | 区块顺序或尺寸不对 | 分区顺序颠倒、弹窗高度写死留白 |
| 文案差异 | 措辞或格式不同 | 页签多「圣物」前缀、缺 `Lv.`、`+1.2%` |
| 状态差异 | 同一状态下的表现不同 | 禁用态样式、置灰规则不一致 |

**同一类问题跨多个界面时合并成一张图**（例如三个页签文案问题放一张，用多组区域上下对照）。

## 第 6 步 画标注图

脚本：`scripts/annotate-ui-diff.py`（依赖 Pillow，数据格式见 `--print-schema`）。

```bash
python "<SKILL_DIR>/scripts/annotate-ui-diff.py" \
  --spec "<版本>/UI对照/ui-diff.json" \
  --effect-dir "<版本>/UI效果图" \
  --game-dir "<版本>/UI对照/工程截图" \
  --out-dir "<版本>/UI对照/标注"
```

一张图 = 一条 `regions` 记录 = 一类问题；版式固定为左效果图 / 右工程，绿框标效果图、红框标工程。

出图纪律：

- **每张图只标一类问题**，这是用户明确要求的；同类多处就多画框，不要换图。
- 文字问题用**整行横带**（宽取满、高 90 左右），不要卡像素。
- 坐标先大后小：先裁一大块出图看，再收窄，比凭感觉写死快。
- 左右可用不同 crop（`crop_effect` / `crop_game`），因为两边同一元素位置常差几十像素。
- 说明文字写**差异本身**，不要写「符合需求」「需要优化」。
- 效果图一侧没有该元素时，让绿框空着也画上，读者才知道「这里是空的」。

## 第 7 步 进对照页

界面问题在对照页里**单列一节 `U`**，编号 `U1…Un`，`reqs` 的「原文」写**效果图文件名 + 该图要求的做法**——
界面外观的依据就是效果图本身，不要去定稿里硬凑一条不相干的规则。

```json
"spec": {
  "U": ["界面外观（依据：v1.0/UI效果图）",
        "U1|圣物抽卡.png：抽取按钮下方有「跳过动画」勾选\nU2|属性总览.png：先冒险属性后军团属性"]
}
```

```json
{
  "id": "U1",
  "cat": "missing",
  "title": "抽卡按钮下方缺跳过动画勾选",
  "where": "UI效果图/圣物抽卡.png × 工程截图/圣物抽卡.png",
  "now": "两个抽取按钮下方直接是页签，没有勾选项。",
  "why": "玩家无法关闭抽卡动画。",
  "reqs": [["U1", "圣物抽卡.png：抽取按钮下方提供「跳过动画」勾选"]],
  "check": "进抽卡页：两个按钮下方出现「跳过动画」勾选项，勾上后抽卡不播动画。",
  "shots": [
    { "src": "…/UI对照/标注/C1_圣物抽卡_缺失元素_跳过动画.png",
      "caption": "效果图有勾选（绿框），工程该位置为空（红框）" }
  ]
}
```

- 图片先压到**宽 1000px 左右**再嵌，否则单文件页会到几十 MB。
- 一条 issue 可挂多张，页面按顺序铺开，点图放大。
- 图片找不到会直接报硬错误，不会静默出空图。
- 效果图本身没画清、两种理解都通时，`cat` 用 `unknown`，`check` 写「策划确认后补」。

渲染：

```bash
node "<SKILL_DIR>/scripts/build-check-page.mjs" --data check.json --out 圣物系统_核查对照_v1.0.html
```

自检输出会打印「标注图：N 张，已内嵌 X MB」。超过 16 MB 会给 warning，先压图。

## 常见误判

| 看着像问题，其实不是 | 原因 |
| --- | --- |
| 列表条数、星级、数量对不上 | 数据生成，不是样式 |
| 空槽 / 已装备顺序不同 | 取决于玩家填了哪个槽，不是排版错 |
| 效果图按钮是英文 | 设计稿占位 |
| 弹窗被背景挡住 | 截图时机，不是层级错 |
| 品质色不同 | 同一套 UI 换底图资源 |
| 角色立绘、背景美术不同 | 素材替换，不是 UI 问题 |

反过来，**容易漏的真问题**：

- 装饰被遮罩压暗（层级顺序），亮度差一截
- 角标缺一半（有角标底但没图标）
- 数值格式（小数位、正负号、单位）不统一
- 弹窗高度写死，内容少时底部一片留白
- 同一元素在 A 页有底板、B 页没有
